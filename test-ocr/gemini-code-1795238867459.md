**关键工程要求**：
- **断点续跑**：`02_run_engine.py --resume` 自动跳过已有有效 JSON 输出的页面；单页超时或报错只记录失败状态并继续下一页，不中断整批。
- **冷启动与稳态耗时严格分离**：每个引擎加载完模型后，记录 `cold_start_sec`；然后对所有样本连续推理，单独计算**剔除第 1 页预热后的 `steady_sec_per_page`**（如样本仅 1 页冒烟则标注 `warmup_only`）。
- **显存硬限制写入代码**：PyTorch 引擎入口强制加 `torch.cuda.set_per_process_memory_fraction(0.75)` 与 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`；ONNX Runtime GPU 强制配 `gpu_mem_limit` ≤ 3.5 GiB；`llama-server` 限制上下文长度（如 `--ctx-size 4096`）并选用 Q4_K_M 或 Q8_0 量化。

## 阶段 3：公平且防作弊的评测脚本（`03_eval_report.py`）

严禁只算单一 `word_recall`。请先检查 `gold_real` 的文本格式，然后实现**两层对齐评测**：

1. **公平文本规范化（Canonicalization）**：
   - 在计算文字保真指标前，对预测文本与 `gold_real` 执行**完全一致的轻量清洗**：剥离纯格式标记（如 Markdown 标题 `#`、加粗 `**`、HTML 标签）、统一连字符断行与多余空白——防止纯文本引擎（Tesseract）与 Markdown 引擎（MinerU/VLM）因格式符号不同造成 CER 失真。
   - 保留原始字符大小写和所有重音/特殊字母（**禁止做 Unicode 降级去重音**）。

2. **每页必须输出以下指标（写入 `per_page.csv`，并按引擎 + 按 `page_type` 分组汇总到 `metrics_summary.csv` 和 `report.md`）**：
   - `cer`：顺序敏感字符错误率（编辑距离 / 金标字符数，越低越好）
   - `word_recall`、`word_precision`、`word_f1`：无序词袋指标（成对暴露“静默漏行”与“幻觉多字”）
   - `order_gap`：`word_f1` 减去顺序敏感词准确率（直接量化多栏串行/乱序程度）
   - `diacritic_acc`：特殊重音与欧系字符（`á é í ó ú ñ ü ö ä ß` 等）及数字编号的精确召回率
   - `len_ratio`：预测字数 / 金标字数（自动标记 `<0.85` 漏段、`>1.20` 复读或幻觉）
   - `cold_start_sec`、`steady_sec_per_page`、`est_days_per_100k_pages`（按单机 24h 折算 10 万页所需天数）
   - `peak_vram_mib`、`vram_spill`（是否 >5200 MiB）

3. **附加两项极具决策价值的分析输出**：
   - **置信度路由可行性统计（`routing_analysis`）**：对自带置信度的引擎（E1/E2 Tesseract TSV `conf`、E3 RapidOCR 行置信度、E5 Surya 块置信度），输出各页的 `conf_mean`、`conf_p10`（最低 10% 分位）以及与真实 `cer` 的相关性，检验“低置信度拦截给更强模型”会不会出现高分漏判。
   - **精简错例诊断（`error_samples.md`）**：为每个引擎自动抽取 CER 最差的 2 页，仅展示最长不超过 15 行的局部 diff 片段，一眼看清错因（漏脚注 / 双栏串行 / 哥特体乱码 / 重音丢失 / 复读）。
