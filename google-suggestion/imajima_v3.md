## 一、架构级缺陷与文档内部矛盾（非 Codex 重复项）

以下 8 项均位于第 9 节 Codex 两轮修订清单之外。

### 1. "斜体学名保护"缺少上游数据源 【已确证：架构断链】

* **原稿位置**：第 2 节、第 4.D 节、第 9 节。

* **问题**：闸口要求"数字和斜体学名按出现次数保护，不得丢"，但输入是文字层 0 字符的整页扫描 PDF，且上游仅持有 PP-OCRv5 server 的行框缓存（框、文本、置信度、页宽）。

* **依据**：【已确证】PaddleOCR（含 PP-OCRv5）标准识别协议仅输出文本框多边形坐标、文本字符串与置信度，**不包含字体样式（斜体/正体）元数据**。上游从未提取过斜体属性，下游闸口没有参照基准来判定原书哪些拉丁词为斜体。

* **修复建议**：在 B 内容层依据《国际动物命名法规》（ICZN）规则构建确定性学名识别器（属名 + 种加词 + 亚种加词置斜体；`sp.`、`n. sp.`、`cf.`、`sensu`、命名人、年份及科以上阶元置正体），先产出结构化 `taxon_span` 实体清单，再由闸口校验已标注学名实体的出现次数守恒。

### 2. Google 官方计价口径与 $\le \text{¥}2/\text{卷}$ 预算存在算术矛盾 【已确证：公式矛盾；字符量未定】

* **原稿位置**：第 1 节、第 4.C 节、第 6 节。

* **问题**：方案规定英文链、中文链均调用 Google 初稿，且两链与审校共享每卷 $\le \text{¥}2$（约 $\$0.3$）预算，同时规定"未知价格不得放行"。

* **依据与算术推导**：

  * 【已确证】据 Google Cloud Translation 官方公开定价（2026 年 11 月核实）：Basic v2 与 Advanced v3 NMT 均为 $\$20 / 10^6$ **字符**（按汇率 7.2 计约 $\text{¥}144 / 10^6$ 字符），每个结算账号每月含 $500{,}000$ **字符免费额度**（按月重置）。

  * 【已确证】Google Cloud Translation 与 Azure Translator 均按 Unicode 码点计费，**若使用 `format=html` 发送 `<span translate="no">` 等保护标签，HTML 标签本身的所有字符全部计入计费字符数**。

  * 【推测】三卷总计 $1{,}130$ 页（361 / 406 / 363 页）。扣除整页图版、目录与空白后，按分类学志书常见密度估算每卷约 $200\text{--}300$ 文本等效页、每页约 $800\text{--}1{,}200$ 日文字符，即单卷净源文本约 $1.6\times 10^5\text{--}3.6\times 10^5$ 字符（实际值 **【未定】**，须阶段 0 统计 OCR 缓存确认）。

  * 两条独立链（日 $\to$ 英、日 $\to$ 中）调用量翻倍，单卷达 $3.2\times 10^5\text{--}7.2\times 10^5$ 字符（三卷合计约 $1.0\times 10^6\text{--}2.2\times 10^6$ 字符）。

  * 若按付费口径：即便按极低估算（单卷双链合计 $2\times 10^5$ 字符），费用亦为 $\$4.0$（约 $\text{¥}29$），超预算 **14 倍**；按 $3.2\times 10^5\text{--}7.2\times 10^5$ 字符计则需 $\text{¥}46\text{--}\text{¥}104/\text{卷}$。

* **隐蔽合规与可靠性风险**：第 4.C 节写"免费则记 0 元并注明"，存在两条完全不同的实现路径：

  1. **官方 API 免费额度**：合法且确定，但 Google 每月仅 $5\times 10^5$ 字符，三卷需跨 3–5 个自然月执行，且程序内必须加字符级硬熔断（超过即中止，防自动扣费）；相比之下，【已确证】**Azure Translator F0 独立免费资源**提供 **每月** $2\times 10^6$ **字符永久免费且硬封顶不产生超额扣费**（S1 付费为 $\$10 / 10^6$ 字符，为 Google 一半），更适合零预算批量跑通。

  2. **非官方网页抓取（如 `googletrans` 调网页端）**：违反服务条款，存在 HTTP 429 限流、静默截断与结果不可复现风险，与本方案"反静默"硬约束直接冲突。

### 3. 阶段 2 指标与"正文零模型"自相矛盾，且 `presub` "成本逐卷递减"论证不成立 【已确证：文档内部矛盾】

* **原稿位置**：第 1 节、第 4.C 节、第 6 节（阶段 2）。

* **矛盾一（残余旧指标）**：第 1 节硬约束明确"正文翻译零大模型；大模型至多用于检索表疑点核对"，第 4.C 节亦重申"不用模型改写。仅检索表疑点段可进模型"；但第 6 节阶段 2 验收标准仍写着 **"命中率逐卷升；模型处理段占比** $<15\%$**（现 72–94%）"**。

  * **诊断**：该指标显然是历史上 DeepSeek 改写旧流程的遗留口径。若正文零模型、仅检索表极少数疑点进模型，全书模型处理段占比应接近 $0\%$（远低于 $1\%$），而非以 $<15\%$ 为目标。

* **矛盾二（降本公式错误）**：第 4.C 节称"映射库按 2009 $\to$ 2001 $\to$ 2007 顺序累积学习，成本逐卷递减"。

  * **依据**：【已确证】Google Cloud Translation 按**输入字符数**计费，不按"未登录术语数"计费。将日文短汉字术语（如 3 字符 `口前葉`、2 字符 `剛毛`）前置替换为英文长词（10 字符 `prostomium`、7 字符 `chaetae`）再送入 Google API，反而**使每卷送译字符数膨胀** $15\%\text{--}35\%$，付费成本不降反升！只有当句级缓存命中整句或模板句跳过 API 时，调用成本才会下降。

### 4. 中文链"译后替换"与英文链"明文前置替换"均存在已证实的 NMT 退化机制 【已确证：算法脆弱】

* **原稿位置**：第 4.C 节。

* **问题一（中文链译后确定性替换失效）**：【已确证】神经机器翻译（NMT）在领域外文本上存在显著词汇漂移（Koehn & Knowles, ACL NMT Workshop 2017）。同一日文多毛类术语在不同句境下会被通用引擎译为多种日常近义词（如 `剛毛` 译作"刚毛/硬毛/刷毛/刺毛"，`背鬚` 译作"背须/背触须/背部的须"）。在中文译文侧做字符串替换，无法穷举机翻产生的未知同义词，导致漏替且不会触发冲突告警。

* **问题二（英文链裸明文 `presub` 破坏句法）**：【已确证】Song et al.（NAACL 2019）与 Dinu et al.（ACL 2019）对受限术语翻译的研究明确指出，在源句中直接用目标语词替换源语词构成语码转换（Code-switching）输入时，**未经专门混合语料微调的通用 NMT 模型**极易出现忽略嵌入词、重复翻译、破坏格助词依存或篡改英文词形等问题。

* **修复建议**：两条链的术语锚定均应上移到**源语言（日文）侧**，并在阶段 0 做对照实验（详见第 8 节问题 2）。

### 5. 条目字段硬校验与现实出版结构冲突，且补丁锚点缺乏抗漂移设计 【已确证：逻辑冲突】

* **原稿位置**：第 1 节、第 3 节、第 4.B 节、第 4.D 节。

* **冲突一（条目字段必选/条件未分）**：第 1 节要求"种条目顺序固定：拉丁名 $\to$ 日文名 $\to$ 中文名 $\to$ 文献 $\to$ 描述 $\to$ 分布 $\to$ 图 $\to$ 图注"，同时规定"没有已核名的类群保留拉丁名"；第 4.B 节则写"字段缺失或顺序错 $\to$ 告警"。

  * 这会引发三类必然误报：① 无 `yiku` 已核中文名的种，究竟省略"中文名"槽位还是重复填拉丁名？若省略即触发字段缺失告警；② **英文版 PDF** 是否也必须包含"中文名"槽位？原稿未界定中/英两版的字段 Schema 差异；③ 分类学志书中并非每个种都有独立插图（常多个种共用一张拼版图，或仅引用他处旧图），也不是每个种都有文献异名录。必须严格区分 **强制字段（拉丁名、描述）**、**条件字段（中文名、图/图注、文献、分布）** 与 **顺序约束（出现者必须保序）**。

* **冲突二（派生视图 + 文本补丁的级联失效）**：第 3 节规定修改不改 `book_ir.json`，而是写成补丁再重导出；第 4.D 节要求补丁"旧文必须恰好匹配一次"。若上游执行"改术语走补丁再重排"（第 7 节）或修复版面/检索表（`manual_overrides.json` / `keys_fix.json`）导致段落边界微调，下游依赖纯文本精确匹配的补丁就会发生**锚点漂移失效**。

* **修复建议**：补丁必须绑定稳定的 `(page_id, block_stable_id, field_role, base_text_sha256)` 与显式应用顺序（术语层先于人工文本补丁层），并在 `gate` 中加入补丁空转/失配即报错的硬检查。

### 6. "用户只看最终结果"与多处人工闭环存在角色与工时转移矛盾 【已确证：需求冲突】

* **原稿位置**：第 1 节、第 4.A.4 节、第 4.A.6 节、第 4.B 节、第 4.D 节。

* **问题**：第 1 节硬约束明确"用户（分类学家）只看最终结果"，但设计中反复把用户引入中间环节：在 `review_plates.html` 拖框与目视确认、对未命中 `yiku` 的日文术语逐条裁定、在三校预览页做目视核对。

* **风险**：【推测】若 $1{,}130$ 页的图版告警率达 $15\%\text{--}25\%$（约 170–280 页）或 `yiku` 缺口达数百词条，此设计实质上是把省下的几十元 API 费用转移成了分类学家数十小时的高昂人工工时。

* **修复建议**：明确区分两类角色——**工程操作员**（承担图版拖框、OCR 纠错、版面校验、三校抽检）与 **分类学家**（仅承担阶段 0 小样拍板、阶段 2 批量术语缺口表一次性签核、阶段 6 最终交付确认），并在阶段 1 设定人工拖框工时上限指标。

### 7. 跨页图版/图注配对与非条目页面（表格、前言、文献、索引）缺失 【已确证：设计遗漏】

* **原稿位置**：第 4.A.2 节、第 4.A.4 节、第 4.B 节。

* **问题一（跨页配对）**：第 4.A.4 节告警将"有图注无图框；有图框无图注"作为页内规则。但动物志书常见**整页图版位于页** $N$**、图注印在对页** $N-1$ **或** $N+1$ 的版式（Imajima 实际占比 **【未定】**）。页内单页配对将触发大量误报。应支持跨邻页窗口 $[N-1, N+1]$ 通过图号（`Fig. X` / `図 X`）关联配对，未配对再报告警。

* **问题二（角色词表残缺）**：第 4.A.2 节角色词表仅含 `title / entry_head / body / key / caption / header / footer / plate`，完全缺少 **`table`（表格）**、**`toc`（目录）**、**`front_matter`（前言/形态术语图解）**、**`references`（参考文献）**、**`index`（索引）**。整卷运行若无分区隔离，这些页面进入 `treatments.py` 或被误归为 `plate`，将触发大面积错排或阻塞 `gate`。

  2. 第 4.A.4 节的 **`review_plates.html`** 前端交互页面与 **`manual_overrides.json`** 读取器。

  3. 第 4.A.5 节的 **`keys_fix.json`** 补丁回放器。

## 三、第 8 节 8 个具体问题的逐条评审

### 问题 1：图版检测（H_char + RLSA + 图注锚定是否足够？基准与预处理？）

* **结论**：仅靠 H_char + RLSA + 图注锚定在老旧日文扫描志书上**不足以独立稳定达标**【已确证】；在 Imajima 三卷上的具体数值【未定】。**必须先做图像预处理再检测**【已确证】。

* **依据**：

  1. **RLSA 在稀疏线描图上的失效机理**：【已确证】RLSA（Wong, Casey & Wahl, *IBM J. Res. Dev.* 1982）假设二值图无显著倾斜与背景噪声。多毛类分类学插图多为**极细稀疏线描图**（单张拼版含 `a, b, c, d...` 多个分离局部解剖图，空白占比高）：游程阈值小则单幅拼版被劈成碎片，阈值大则跨区吞并图注、正文或书脊黑影。

  2. **公开基准与开源模型实测数据**：

     * **DocLayNet**（Pfitzmann et al., KDD 2022）：证明纯启发式规则在跨版式扫描文档上泛化急剧下降。

     * **PaddleOCR 3.x `PP-DocLayout`**（官方 2025–2026 文档，与当前 PP-OCRv5 同栈）：`PP-DocLayout-L`（RT-DETR-L，123.8 MB）支持 23 类元素（含 `image`、`figure_title`、`table`、`references`、`header`、`footer`、`table_of_contents`），在自建 500 页中英文档评测集上 $\text{mAP}(0.5)=90.4\%$，GPU 推理约 $33.6\text{ ms/页}$（CPU 约 $251\text{--}503\text{ ms/页}$）；**`PP-DocLayout_plus-L`** 额外纳入古籍/老书（ancient books）训练数据，在更难评测集上 $\text{mAP}(0.5)=83.2\%$，GPU 约 $17.2\text{--}53.0\text{ ms/页}$。

     * **DocLayout-YOLO**（Zhao et al., arXiv:2410.12628                                                                                          , 2024）：在 DocSynth-300K 预训练，DocStructBench 综合 （学术论文 、教材 ），推理速度 。

     * **NDL-OCR (`ndl-lab/ndlocr-lite`)**（日本国立国会图书馆开源，截至 2026 年 11 月已迭代至 v1.3.1 / v1.4.0）：基于 DEIM 版面检测器 + PARSeq，专为日文学术与历史扫描书籍训练，原生支持纵排与 `縦中横`。

     * *注*：尚无针对"日文多毛类扫描志书"的公开专用评测集【未确证】。

  3. **预处理依据**：【已确证】Sauvola 自适应局部二值化（Sauvola & Pietikäinen, *Pattern Recognition* 2000）专门克服老旧纸张发黄、装订阴影与背面透字；投影方差纠偏是 RLSA 水平/垂直游程成立的前提。

* **落地建议**：构建**零 API 成本异构双路**：路径 1 = 预处理（纠偏 + Sauvola + 去书脊阴影）+ H_char/RLSA + 图注锚定；路径 2 = 本地 `PP-DocLayout_plus-L`（或 `ndlocr-lite`）。两路 $\text{IoU}$ 低于阈值或检出数量不一致即自动触发 `plates_alerts.json`。

### 问题 2：零模型能走多远？（系统性失败模式？哨兵掩码能否解决？有数据吗？）

* **结论**：零模型 + Google 初稿在分类学描述文上存在 **4 类已确证的系统性失败模式**；哨兵掩码或 API 原生保护可显著压低词汇与实体错误，但**无法突破句法依存错位的质量天花板**【已确证】。Imajima 上的精确错误率【未确证】，须阶段 0 量化。

* **4 类系统性失败模式与依据**：

  1. **专业形态术语泛化为日常词**【已确证】（Koehn & Knowles, 2017）：如 `剛毛`（chaetae/setae）被译为 "bristles/stiff hair"，`疣足`（parapodia）译为 "wart foot"，`口前葉`（prostomium）译为 "pre-oral leaf"。

  2. **拉丁学名与分类学缩写被误译或破坏**【已确证】：常见拉丁形容词根（如 *alba*、*longa*、*major*）或 `n. sp.`、`cf.`、`Fig.` 被误译、拆词或改大小写。

  3. **日文长定语/体言止导致的解剖归属错位**【已确证】：日文分类描述高频省略主语并使用多层连体修饰，NMT 易把修饰"背叶（dorsal lobe）"的数量或形状错挂到"腹叶（ventral lobe）"上。这是**零模型架构无法根治的上限**，只能通过审校抽检识别。

  4. **明文语码转换（`presub`）引发的解码退化**【已确证】（Song et al., NAACL 2019；Dinu et al., ACL 2019）。

* **哨兵掩码 vs API 术语表/HTML 保护的证据对比**：

  * **哨兵掩码（如 `XTAX1X`）**：【已确证】在受限翻译基准（Post & Vilar, NAACL 2018；WMT 2021 Terminology Shared Task, Alam et al., 2021）中，占位符掩码可将术语词面准确率推升至 $>95\%$，但代价明确：① 掩盖词性与单复数特征，导致英文冠词/介词/主谓一致错配；② 商业 NMT 偶发篡改占位符（小写化 `xtax1x`、插空格或丢失），需严格闸口校验。

  * **Google Cloud Translation v3 Glossaries**：【已确证】官方 v3 支持日语（`ja`）单向术语表，且不增加请求文本的 HTML 标签字符数；但需注意 Google 官方文档列出的日语停用词（`ー と は が を に へ の で`）及非空格分词语言的边界切分问题，短术语偶有漏命中【须阶段 0 实测】。

  * **HTML `translate="no"` / `class="notranslate"`**：【已确证】适合保护拉丁学名与数值量纲，但务必注意**计费陷阱**——`<span translate="no">...</span>` 每次包裹消耗 29 个计费字符；若改用最短合法标签（如 `<u translate="no">` 26 字符，或哨兵 `X01X` 仅 4 字符），在严格控预算场景下字符开销差异可达 6 倍。

* **建议**：在阶段 0 对 10 个种描述段做 3 路 A/B 对照（① 裸译、② 短哨兵 `X01X` + 闸口守恒校验、③ Google v3 Glossary + 最短保护标签），同时统计术语命中率、句法错误率与净字符增幅。

### 问题 3：两条独立链（日 $\to$ 中） vs 英文枢纽（日 $\to$ 英 $\to$ 中）

* **结论**：**正文翻译应坚持直接日** $\to$ **中（优于英文枢纽）**【已确证】；但**术语资产建设必须建立日-英-中三语桥梁**【已确证】。多毛类上的精确分差【未确证】。

* **依据**：

  1. **枢纽翻译误差级联**：【已确证】枢纽机器翻译经典研究（Utiyama & Isahara, NAACL 2007；Wu & Wang, ACL 2007；Cheng et al., ACL 2017）表明，两段独立翻译串联会放大语义漂移与信息丢失。

  2. **中日汉字形态术语的高度同源性**：【已确证】日文多毛类解剖词汇大多为汉字复合词（`口前葉`/`口前叶`、`疣足`/`疣足`、`体節`/`体节`、`剛毛`/`刚毛`、`背鬚`/`背须`、`咽頭`/`咽`）。走英文枢纽会先将其转为低频拉丁词根（`prostomium`、`parapodia`、`chaetae`），再从英文译中时通用 NMT 对低频拉丁术语反而更容易音译或错译。

  3. **英文列的不可替代价值**：国内权威形态词典（如全国科技名词委"术语在线"）主要按 **英** $\leftrightarrow$ **中** 检索；保留英文列能极大降低人工补齐 `yiku` 缺口的核查成本。

* **建议**：保持正文双链独立翻译，同时在 B 层以统一 `concept_id` 维护 `JA` $\leftrightarrow$ `EN` $\leftrightarrow$ `ZH` 三语主表。

### 问题 4：日文术语 $\to$ 中文已核名的缺口与可追溯权威来源

* **结论**：`yiku` 对日本多毛类的覆盖率当前【未定】。核心架构调整为：**禁止把"日文和名"直接作为查中文名的主键，改为以"有效拉丁学名（经 WoRMS 异名归并）"作为唯一枢纽**【已确证】，对接以下可追溯权威库（零模型自拟）。

* **已核实的权威数据源清单**（数据源存在性与性质均【已确证】；与 Imajima 三卷的交集率【未定】）：

  1. **WoRMS（World Register of Marine Species，官方 AphiaID REST API）**：【已确证】核心作用有二——① 将 2001/2007/2009 原书旧学名归并到现行有效学名（AphiaID），解决跨 20 年分类修订导致的同物异名漏匹配；② **WoRMS 已官方接入日本 JAMSTEC 的 BISMaL 日文和名数据**，一次调用即可同步获得现行有效学名与权威日文名，但 WoRMS 中文俗名很稀疏，不可作中文名主库。

  2. **Species 2000 China Node（《中国生物物种名录》CoL China）**：【已确证】截至 2026 年官方页面收录多毛纲 `Class Polychaeta` **508 个接受种、328 个异名**（雷雁莉等审定），可作为中国大陆法定优先中文名源。

  3. **《中国海洋生物名录》（刘瑞玉主编，2008，科学出版社）与《中国动物志·无脊椎动物》多毛纲各卷**（孙瑞平、杨德渐等编著）：【已确证】黄海、东海与日本海/太平洋西北部共享大量多毛类区系，经 WoRMS 异名归并后反查上述志书，是扩充 `yiku` 已核中文名的最稳妥可追溯来源。

  4. **TaiCOL（台湾物种名录）**：【已确证】覆盖西太平洋海区广、API 开放，但两岸中文物种名体系有差异，仅可作为次级候选并显式标注来源地区，由用户决定是否采纳。

  5. **全国科学技术名词审定委员会（术语在线 TermOnline）**：【已确证】用于**形态解剖术语**（非物种名）的权威英 $\to$ 中核定。

### 问题 5：预算（$\le \text{¥}2/\text{卷}$ 是否现实？检索表应否完全零模型？）

* **预算结论**：若按官方 Google Cloud Translation 付费计价，$\text{¥}2/\text{卷}$ **完全不现实（差距超过 1 个数量级）**【已确证】。仅存在 3 条可行路径：

  1. **合法白嫖官方永久免费额度**：Google Cloud（$5\times 10^5$ 字符/月，三卷需跨 3–5 个自然月）或 **Azure Translator F0**（$2\times 10^6$ 字符/月，单月或 2 个月即可覆盖全部三卷双链，且资源层硬封顶无超额扣费风险），全流程翻译费 $\text{¥}0$。

  2. **本地零成本开源 NMT**（如 Meta `NLLB-200`、Helsinki-NLP `OPUS-MT` 或本地小参数翻译模型）：费用 $\text{¥}0$，但在日文长定语上的流畅度通常弱于 Google/Azure 商用引擎【推测，需阶段 0 评测】。

  3. **向用户申请调整商业付费预算**：若要求快速一次性跑完商用 Google API，建议预算调整至 $\text{¥}60\text{--}\text{¥}120/\text{卷}$（或 Azure S1 $\text{¥}30\text{--}\text{¥}60/\text{卷}$）。

* **检索表是否完全零模型**：**强烈建议改为完全零模型（`keys check` 图拓扑校验 + 人工修复告警）**【已确证可行性更高】。

  * **依据**：① 第 2 节实测已证明 `docstore keys extract|check` 在小样上以 $\text{¥}0$ 精准验证了 2001/2009 自洽并定位了 2007 断链（`10' p6`）；② 二歧检索表本质是有向无环图（DAG/树），确定性拓扑校验（对偶编号成对、出度 $=2$、无环、无孤立节点、终点均为有效类群/页码）可捕获绝大部分 OCR 损坏；③ 按原稿实测单目录核对 $\text{¥}0.18\text{--}\text{¥}0.31$ 推算，若单卷有 $15\text{--}30$ 个科/属检索表（具体数 **【未定】**），仅检索表模型调用就需 $\text{¥}3\text{--}\text{¥}9$，单此一项就会击穿 $\text{¥}2$ 总预算。

### 问题 6：三审三校的"异模型抽审"是否有必要？有无证据？

* **结论**：在 $\le \text{¥}2/\text{卷}$ 预算与零模型自拟禁令下，**必要性【未确证】且存在引入错误建议的负收益风险**；建议降级为可选项，优先用确定性统计规则替代。

* **依据**：

  * 【已确证】LLM-as-a-Judge 翻译评测研究（Kocmi & Federmann, EAMT 2023 *GEMBA*；后续 GEMBA-MQM 系列）表明，强前沿模型在通用语料上能较好捕捉漏译与流畅度问题，但**在缺乏领域真值词典的高度细分学科中误报率高**（倾向把合法电报体或生僻形态术语判为"不通顺"并要求改写）；低价小模型误判更严重。

  * 在本项目约束下，通用异模型不掌握 `yiku` 边界，可能反向建议编造中文物种名。

* **零成本替代方案**：将审一/审二扩展为确定性高危扫描——① 源/译文长度比 $>2\sigma$ 离群检测（专抓漏译/重复译）；② **否定极性守恒检查**（日文 `ない/なく/無/欠く` $\leftrightarrow$ 英文 `not/no/without/absent/lacking`、中文 `无/不/缺/未`）；③ 假名/旧字残留；④ 数值 + 量纲守恒。仅当预算有余时，对上述极少数离群块触发异模型二分类告警，并严格执行第 4.C 节的"可测改进停用门槛"。

### 问题 7：第 5 节验收指标是否充分？分层样本每层最少多少页？

* **指标缺口**：第 5 节现有指标（召回、精确率、$\text{IoU}$ 中位数/P10、图注配对率、告警召回）设计扎实，但**缺失 3 项防失控指标**【已确证】：

  1. **告警率与告警精确率（Alert Rate & Alert Precision）**：仅考"告警召回"会诱发过度报警（全书 $100\%$ 告警即获 $100\%$ 告警召回，但人工复核崩溃），必须约束全卷触发告警的页占比上限。

  2. **边缘裁切失真率（Edge-Clip Rate）与文本渗漏率（`CAPTION_LEAK` Rate）**：【已确证】$\text{IoU}=0.92$ 的框仍可能切掉边缘比例尺数字或解剖字母 `a`，或把一行图注带入图内，属科学出版硬伤。

  3. **未告警页静默漏检率（Silent Failure Rate on Unalerted Pages）**：直接度量"反静默"承诺是否成立。

* **每层最少样本量（【已确证】二项分布 Wilson 区间与三分法则）**：

  * **阶段 0（每卷 10 页，平均每层 1–2 页）**：仅具**冒烟测试与缺陷暴露意义**，**无统计显著性**（$n=2$ 时 $2/2$ 的 $95\%$ Wilson 置信区间为 $[34.2\%, 100\%]$）。

  * **阶段 1 分层验收**：为将 $90\%$ 召回率的 $95\%$ Wilson 置信区间半宽控制在约 $\pm 10\%\text{--}12\%$ 内，**每个页型层（三卷合并计算）最少需** $n \ge 30$ **页**（如 $27/30$ 对应 $95\%$ 置信区间 $[74.4\%, 96.5\%]$；全书不足 30 页的稀疏页型则全量标注）。

  * **未告警页反静默审计**：依据统计学**三分法则（Rule of Three，Hanley & Lippman-Hand, *JAMA* 1983）**【已确证】，若抽检 $n$ 页未告警页观测到 $0$ 例静默漏检，真实漏检率的 $95\%$ 置信上限为 $p_{\text{upper}} \approx 3/n$（精确公式 $1 - 0.05^{1/n}$）：

    * 证明未告警页静默漏检率 $<5\%$：需随机抽检至少 $n = 60$ **页**（全 0 漏检）；

    * 证明未告警页静默漏检率 $<2\%$：三卷合计需抽检至少 $n = 150$ **页**（每卷 50 页，全 0 漏检）。

## 三、翻译这两本书必须改造的 6 个关键环节

### 1. 输入层分流与欧语文本预处理（当前 v3 空白）

* **优先核查原生矢量文字层**：*Fauna Ibérica* Vol. 48 是 2025 年 9 月由 CSIC 出版的现代开放获取电子书。如果原文件本身带有嵌入式文字层，**应直接走原生 PDF 解析通道**（提取字符坐标、矢量斜体字体与嵌入图片对象），跳过 OCR 与纯 CV 裁图，既能直接拿到 100% 准确的斜体学名元数据，又能避免图内文字误识出乱码（如第 93、98 页的异常字符）。


* **必须新增欧语断词合并（De-hyphenation）**：两本书几乎每页都有大量行尾连字符断词，例如西语 `penín- sula`、`Apis- tobranchidae`、`pseudo- compuestos`，德语 `berück- sichtigt`、`ursprüngli- chen`、`Zähnchen- reihen`。直接送入机器翻译或术语匹配会彻底破坏词形。必须引入“词典感知的断词合并器”，同时保留合法的复合词连字符（如 `Hartmann-Schröder`、`íbero-balear`、`Dorsal- und Ventralcirren`、`gelblich-braun`）。


* **页眉穿插剥离与边缘噪声过滤**：*Fauna Ibérica* 的页眉 `ANNELIDA, POLYCHAETA VII` 频繁穿插到图注正中间（如 Fig. 3、Fig. 6），必须在拼装图注前按版心 $y$ 坐标硬剥离页眉/页脚。Hartmann-Schröder (1996) 的老旧扫描存在馆藏印章、右边缘字迹裁切（如前言第 6 页） 和邻页书脊边缘的竖排残字（如第 30、48、75 页），必须按之前评审意见补齐 **Step 1 图像预处理（去书脊黑影、裁除版心外缘噪点、Sauvola 二值化）**，且德语 OCR 需切换或微调对变音符（`ä/ö/ü/ß`）和 `‰` 符号友好的模型。



### 2. 图版检测与图注配对改造

* **`PROTECTED_LABEL` 与图片内译文策略**：两本书的插图内部不仅有 `A–N` / `a–g` 编号，还包含大量**解剖结构说明文字与比例尺**（例如 *Fauna Ibérica* Fig. 1、Fig. 3 中的 `portador maxilar`、`parápodos modificados`、`branquia (b)`、`cirro dorsal (cd)`；Hartmann-Schröder Abb. 2、3、5、29、58 中的 `Pr`、`dc`、`Mdm`、`Mdrt`、`1.-3.tc`、`200 µm`）。A 层必须先区分“图内解剖标签”与“正文/图注”，严禁误擦图内文字；同时需决定图内西/德文全拼标签是保留原字并在图注附对照，还是做图层替换。


* **放宽图号正则与支持跨页配对**：*Fauna Ibérica* 存在 `Fig. 12'` 与 `Fig. 16'` 这类带撇号图号，且大量图注采用缩写 `figs. 2A-C`；Hartmann-Schröder 的 `Abb. 22` 存在图在 68 页、图注落在 69 页底部的跨页分离现象。图号连续性检查必须支持撇号后缀，图版-图注配对窗口须从“单页”扩展为 `[页 N-1, 页 N, 页 N+1]`。


* **多通道画质处理**：*Fauna Ibérica* 同时包含黑白线描图、电镜照片（MEB，如 Fig. 2、Fig. 23D–G）和实物照片（如 Fig. 12、Fig. 16），若用统一二值化处理会毁坏电镜与照片灰阶，必须按“线描图 / 灰度照片”双通道分流。



### 3. 检索表提取规则泛化

* **适配无 `1'` 编号与无点线格式**：v3 的检索表逻辑主要验证于 Imajima（带 `10'` 偶句与引导点线）。这两本欧洲书的检索表均采用“只标首项数字（`1.` 或 `1`）、第二项省略编号”的格式，且 Hartmann-Schröder 的多处检索表**没有引导点线**，OCR 极易把多层偶句编号挤成一列（如第 27 页 `17 18`、第 44 页 `3 4 5 6 8 7 8`）。提取器不能只靠文本正则，必须依赖**左侧编号列 $x$ 坐标 + 右侧目标列（`(p. XX)` / `S. XX` / 跳转数字）$x$ 坐标**的二维几何聚类。


* **支持检索表脚注与多语跳转标签**：*Fauna Ibérica* 的 `Clave de géneros` 中存在带星号脚注的终点（`Paraprionospio *`），排版与拓扑检查器需允许“非页码终点（附脚注说明）”合法通过，避免触发误报。



### 4. 条目 Schema 插件化与科学公式保护

* **废弃硬编码的“固定 8 字段顺序”**：两本书的物种条目结构各不相同，且都不含日文名。应把 v3 的顺序检查器改为**按书系配置的 Schema（`book_profile.yaml`）**：


* *Fauna Ibérica* 配置：`taxon_head` → `synonymy_orig` → `description` → `source_note`（可选）→ `taxonomic_remarks`（可选）→ `distribution`（`Distribución geográfica`）→ `biology`（`Biología`）。


* Hartmann-Schröder 配置：允许“完整条目”（`description` → `Färbung` → `Verbreitung` → `Ökologie` → `Biologie` → `Taxonomische Bemerkung`）与“简略条目”（仅 `description` → `Färbung` → `Verbreitung`）并存。




* **扩充页面角色与跳过免译区**：两本书末尾均有极长的**参考文献**、**同物异名附录**与**双栏学名索引**（*Fauna Ibérica* p. 395–470 占 76 页；Hartmann-Schröder p. 598–650 占 53 页）。应在角色分区中新增 `front_matter / family_intro / checklist / table / references / appendix_synonymy / index`，对参考文献、同物异名录与索引执行 **Tier 0 零翻译直通**，直接省去 15%–20% 的翻译字符量。


* **新增科学公式与欧式数值保护层**：在送译前用不可译标签/占位符锁定两类高频结构，并在闸口按出现次数与量纲校验：
* 颚式与化学式：`Mx I=1+1, Mx II=12-15+12-14, Mx III=10-12+0`、`C12H22O24P3`；


* 叶须虫科触须/刚节公式：`1+O a1/a1 + B a1/aN`；


* 欧式数字格式转换规则：将小数逗号（`1,8 mm`）与千位句点（`5.275 m`） 在标准化层显式区分，防止数字闸口或英文版产出出现千倍数量级歧义（如把 5275 米误译为 5.275 米）。





### 5. 翻译链路与预算策略调整

* **翻译链路方向变化（英语枢纽在此优于直译）**：对于日文志书，中日汉字同源让“日→中”直译占优；但对**西班牙语和德语**，其多毛类解剖词汇（如西语 `ceratóforos`、`lóbulos presetales`、`ganchos subaciculares encapuchados`；德语 `Elytrophoren`、`Dorsalcirren`、`Nuchalorgane`、`spiniger`/`falciger`）与英语同源度极高。采用 **西/德 → 英 → 中**（或以英语术语为桥接挂载 `yiku` 与全国科技名词委词典），术语映射成功率远高于直接维护西→中、德→中词表。


* **零大模型在长文段落的质量风险**：这两本书的科级综述、生态学与生物学段落均为复杂学术长句（尤其是德语动词后置与多层嵌套从句）。如果严格执行 v3“正文零大模型改写”约束，建议在输出定位上向读者明确区分：**形态描述与检索表**以“术语精准 + 实体零丢失”为第一目标，**生态/综述长文**接受机翻直译可读性；或仅对综述/讨论类长文放开低价模型润色。


* **预算与免费配额现实**：470 页西语与 650 页德语书的净字符量远大于单卷 Imajima[cite: 1, 2, 3]，若走付费翻译 API，¥2/卷的预算 会被击穿数十倍。如果必须维持近零成本，工程上需要配套 **SQLite 句级缓存 + 跳过免译附录/文献 + 官方免费额度池（或本地开源 NMT 模型）分批调度**。
