# 检索表格式规范（草案 v1，2026-11-23；第四节已审定）

> 写规则原则：凡随目标语言或原书而变的体例，一律做成 profile 参数并写明默认推定规则，不作为「全书统一二选一」去问用户。

依据：research/web_rules.md（网络）、research/local_keys.md（N 盘多毛类文献 16 篇）、research/zh_keys.md（中文专著 6 例）。
每条规则标「可自动查」= 工具必须能检查；标「待定」= 体例选择，等用户定，定后全书统一。
状态：已确证（≥2 独立来源或主线程看过页图）/ 单源 / 未确证。

## 四、体例参数（profile，按语言与原书取默认，用户可覆盖）

用户 2026-11-23 审定：下列四项不是全书统一的二选一，而是随目标语言、原书 PDF 而变的参数。keykit 必须支持在 profile 中选择；默认值按下表推定，用户指定的值优先。

| 参数 | 取值 | 默认推定规则 | 依据 |
|---|---|---|---|
| `second_lead` 第二分支标记 | `dash`（—）/ `prime`（1'）/ `backref`（2 (1)，括号为上一级号）/ `serial`（1 (4)、4 (1)，每条独立编号，括号为对立条号）/ `number`（每条独立编号） | 取原书 PDF 的体例（从源文检测；Imajima 日文原书为 1'） | 用户审定；research/zh_keys.md 第 52、85、94 行（国内志书多用 `1 (2)` 对照式或首条编号） |
| `overflow` 长正文去向 | `wrap`（A：折行，末行尾字接点线与去向）/ `fill`（B：点线填满再换行） | 目标语言中文 → `wrap`；英文 → `fill`（ZooKeys 模板） | research/zh_keys.md 第 97、111 行；web_rules.md；两者都须满足 L5 |
| `figref` 图号位置 | `before`（去向前，Zootaxa）/ `after`（去向后）/ `source` | `source`：照原书；用户排版时可选 | 用户审定 |
| `dest_zh_name` 去向加中文名 | `on` / `off` | 目标语言中文 → `on`（「中文名 + 半角空格 + 斜体学名」）；英文等 → `off` | research/zh_keys.md 第 13、28、41、95–96 行（国内志书去向均带中文名） |

- `dest_zh_name=on` 时中文名只取 yiku（已核优先）；yiku 无名则只写学名并列入报告，不得临时拟名（AGENTS.md 第 3 节）。
- 检测原书体例失败时，报「未确证」并要求用户指定，不静默套默认值。

## 六、吸收 test-keys/code_artifact2.md（2026-11-23 评估）

该文为网络/模型整理稿，未注明作者。主线程逐项核对后只吸收下列内容；其余为通用知识或与翻译排版无关。

**已核对的引文**（crossref/datacite 查 DOI，2026-11-23）：Packer 2024 ZooKeys 1215 `10.3897/zookeys.1215.130416`；Tofilski 2018 ZooKeys 735 `10.3897/zookeys.735.21412`（DKey）；Glasby 2025 ANNiKEY Interactive `10.5281/zenodo.13738485`。文中其他文献与开源工具描述（Clavis、clavis-pipeline 的 LLM 抽取等）未核对，**未确证**。

**吸收**
1. 新增 L8（右折行边界统一）、T6（属种不断行）；`second_lead` 增加 `serial` 值（中文志书的连续平行式）。
2. **L5 的实现方法改为「排版引擎自己折行」，不再估算字宽**。现 `builder.couplet_para`（keykit/builder.py 约 895–940 行）用 `last_line_mm()` 估算末行宽度再决定是否另起一行，估错就产生 p6 那种留白尾巴。替代做法：
   - Word：段落设右缩进 = 去向列宽；右对齐带点前导符的制表位放在版心右缘（右缩进之外）。正文在右缩进处折行，末行按 Tab 越过右缩进，点线直通去向。
   - TeX：`\rightskip` = 去向列宽，`\parfillskip = -\rightskip`，点线用 `\leaders`（与 LaTeX 目录 `\@dottedtocline` 同理）。`\leaders` 的点按外层盒子网格对齐，上下行点位一致。
   - 这天然给出 L5(A) 折行式。L5(B) 点线填满式仍需另行实现。
   - **样张验证结果（2026-11-23，keykit/proto/tabtest.py，8 条分支，含中英文、长去向）**：
     - 普通段落 + 悬挂缩进：Word 全部正确；LibreOffice 对**多行**分支把越界制表位按左缩进偏移（悬挂 12 mm 时去向越出版心约 12 mm，改 20 mm 则越出约 20 mm），单行分支正确。在 docx 里设 compatibilityMode=15 后，LibreOffice 改为把制表位截在右缩进处，去向不再到右缘，同样不合格。
     - **两列无框固定宽表**（编号列 + 正文列；正文段落左缩进 0、右缩进 = 去向通道宽，点线右对齐制表位设在单元格右缘）：**Word 与 LibreOffice 都正确**，所有去向右对齐到版心右缘，正文在通道左边界统一折行。LibreOffice 必须写明 `tblGrid/gridCol` 宽度，否则列宽失效。
     - 结论：L5 改用两列无框表实现，不估算字宽。booklayout 出 PDF 用的是 LibreOffice（booklayout/cli.py 第 240 行），所以只能用表格方案。
     - 尚未覆盖：去向宽于通道时会压到正文（通道宽须按全表最长去向计算，见 L8）；LibreOffice 在中文与数字之间自动加的间距与 Word 不同。
3. 发现缺陷：`builder.clean_text`（keykit/builder.py 第 175 行）把 NBSP 替换为普通空格，T6 无法在排版阶段落实。改时只在学名内部保留 NBSP。
4. 已有覆盖，不重复实现：死链、孤立号、环路、回指号不符、重号（keygraph.py、keymodel.py）；偶句不跨页（builder 第 916–917 行 keep_together/keep_with_next，对应 L6）。

**不吸收**
- 语义质检（数值区间重叠、「较长」类模糊词、非对立性状、树平衡度）：这些审的是原作者的内容。译者不改原文，最多作为给人看的提示，不进 gate。
- 由性状矩阵自动生成检索表（§4.4）：与翻译排版无关。
- 文中 Typst/LaTeX/CSS 模板代码：本项目排版走 DOCX，只取原理，不搬代码。
