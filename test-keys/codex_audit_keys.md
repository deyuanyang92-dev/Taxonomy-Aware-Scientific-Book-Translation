# 二歧检索表全链路代码审查

**结论：五个环节都有实现，默认发布链仍可漏过整张检索表、错误去向和未复核的 PDF。** 最严重的断点在发布入口：`publish_book.py` 的 `keycheck` 阶段实际调用 `key-model`，后者允许原译两侧均识别到零张表时成功。PDF 闸口读取的是短引导线和断行报告，文档要求的 KR1–KR7 独立报告没有接入该闸口。`1a/1b` 表在两个入口的识别结果确实不同，已用内存反例复现。依据：`scripts/publish_book.py:102–130`、`booklayout/keymodel.py:345–361`、`booklayout/cli.py:1725–1749,1752–1773`、`docs/booklayout.md:299–315`。

## B. 通用性与硬编码

| 位置 | 已确认的假设及影响 |
|---|---|
| **Imajima 三卷与 PP-OCR** | 默认 TOML 由 2001、2007、2009 三卷标定。标题用 `検索/Key to/KEY TO`，终止词用日英图表题和日文文献标题，类群词含 `亜科/科/属`，固定纠正 `区→図`。编号在页左、去向靠右，部分距离是 200 dpi 像素。规则可配置，但 Python 尾部补读仍要求 `図`、CJK 句末等特征。换语种、栏宽或分辨率后，单换标题正则不足。依据：`docstore/rules/keys.toml:13–37,39–66`、`docstore/keys.py:477–500,536–565`。 |
| **行尾 OCR 与手工拆段** | `keytail` 裁最后 16% 页宽，使用固定边距、倍率、Tesseract 单行数字白名单，接受第一个“本表存在且比当前号大”的 1–3 位数。因此左栏终点、合法回跳、文字终点不能靠它恢复，邻行若给出合法号也可能被采纳。`keysplit` 要求同段至少两处“括号内 `図N` 后紧接日文字符”，只解决一种粘段。实页回归固定为三卷，允许缺缓存、PDF 或 Tesseract 时跳过。依据：`docstore/keytail.py:21–23,45–78,94–104`、`scripts/keysplit.py:1–19`、`tests/test_docstore_keytail_real.py:12–42`。 |
| **按卷统计与专书版式** | `keys_report --imajima` 固定缓存哈希、卷页数、历史基线、引擎目录名；其他书可用 `--volume`，但缺缓存或有残留仍可退出 0。`imajima.py` 明确是专书模板，固定开本、缩进、行距、引导线长度，按 CJK/西文两种字宽估算；`key_line()` 直接取全局 `LAYOUT`。Rouse 在 builder 可见的是作者连词示例；指定链路中按 Rouse 书名切换逻辑**未确证**。依据：`scripts/keys_report.py:24–45,75–108`、`booklayout/imajima.py:2–8,42–55,157–184`、`booklayout/builder.py:55`。 |
| **Fauna Ibérica 与分页 Markdown** | `keyalign` 内置 `FAUNA IBÉRICA`、`IBERIAN FAUNA`、`ANNELIDA, POLYCHAETA` 页眉，以 `<!-- PDF p.N -->` 及紧邻下一页分段；重切起点为 `•` 或 1–2 位数字加点，终点锚为 `(p. N)`、作者年份、数字或 ASCII 末词。脚注锚还要求大写拉丁字母。`keyfix` 用 `Key/Clave/检索表`、拉丁名加页码、160 字以内短块和页内相邻关系修复；纯 `couplet` 页不触发。跨页续行、其他页码写法、较长译句和混合索引页行为不同。依据：`booklayout/keyalign.py:22–32,44–76,164–176,246–261`、`booklayout/keyfix.py:16–43,53–82`。 |
| **`1/1′`、`1a/1b`、`1(3)`、`1—2`** | Markdown 主解析器要求数字加点及空白，或项目符号；裸 `1/1′`、a/b、括号回指不走同一文法。aligned 检查器能读 a/b 和括号内的号，却按外部编号分组；真正检查 `1(3)↔3(1)` 的是按页的 `transqa`。范围去向又有第三套语法：`key-model` 接受 `1-2`、`1–2`，验证时仅按 ASCII `-` 切且只查左端；字面 `1—2` 落入 `taxon`。`keycheck` 数字去向只接受单号，去向上的撇号被转成整数而丢失。依据：`booklayout/keymodel.py:28–37,67–75,200–214`、`booklayout/keycheck.py:69–75,151–175,393–402`、`transqa/blocks.py:58–59`、`transqa/taxonomy.py:39–62`。 |
| **缩进式、原生表格、多入口、图示检索表** | Markdown 逐行 `strip()`，层级缩进无法建边；分支模型只有文本编号和去向，没有表格单元格坐标、入口集合、图节点或热区。builder 能**输出**三列表；VL 把图像裁出并跳过，不会从图中连线建图。`keycheck` 默认最小号为唯一豁免入口，其他合法入口可能被报孤立。上述四类可保留原貌并端到端校验的实现**未确证**。依据：`booklayout/keymodel.py:41–64,137–169`、`booklayout/keycheck.py:455–462`、`booklayout/builder.py:1005–1029`、`scripts/vl_to_aligned.py:63–79`。 |
| **语言与命名法** | `key-model` 的标题覆盖英、西、德、法、日和简繁中文；aligned 检查器的标题词表更窄，页码只列 `p./pp./pág./S./第…页`。俄文或拉丁文整表可因编号而部分识别，但标题、分页和目标解析的通用性**未确证**。`StructDoc` 仅在原文含 CJK 时查正文双名；`transqa` 学名核对依赖斜体，OCR 丢斜体会失去这层保障。builder 地址斜体依赖 ASCII 词形、英语词表和有限高阶元后缀，KR6 复用同一判断，二者可能共同漏错。依据：`booklayout/keymodel.py:31–38,149–156`、`booklayout/keycheck.py:74–86`、`docstore/structdoc.py:267–286`、`transqa/taxonomy.py:24–37`、`booklayout/builder.py:675–693`、`booklayout/keyrender.py:242–248`、`docs/taxonomic_typography.md:3–22`。 |
| **PaddleOCR-VL、文本层 PDF 与标记丢失** | VL 转换硬取 JSONL 第一条、`layoutParsingResults[0].prunedResult`、同页 PNG 和固定标签；至少半数行匹配才判 key，原译多行数不等会保留旧块。无译文时以原文充当译文，已有目标但译文缺点线时又可能追加一次源目标。PP-OCR 则要求 `pNNNN.json` 的 `width/rows`。成品 PDF 复核反过来依赖文本层字符框和字体标志，按整页相同基线合行，纯图页或双栏不能由该规则可靠复核。`keymarkers` 对原译两侧都查，但至少三处点线才报警，索引块达四分之一即跳页。依据：`scripts/vl_to_aligned.py:17–37,55–76,103–117`、`docstore/keys.py:691–702`、`booklayout/keyrender.py:101–126,155–172`、`booklayout/keymarkers.py:23–49,58–75`。 |
