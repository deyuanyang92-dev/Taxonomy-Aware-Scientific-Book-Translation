# 02. 多场景逻辑切分与结构清单设计

## 1. 设计目标与问题收敛

当前仓库的结构识别逻辑分散在 `docstore/`（块分类与检索表）、`scripts/`（`chapter_split.py`、`chapter_manifest.py`、`split_check.py`）、`taxadb/split.py`（分类志条目切分）以及 `booklayout/`（`contents.py`、`structure.py`、`furniture.py`）中。

本模块的核心优化是：
1. **切分粒度升级到块级坐标 `[page, block_idx]`**：彻底解决“半页起新章”和跨页截断问题。
2. **统一路由策略**：在 `scripts/chapter_split.py` 中收敛为 4 级降级（Waterfall）策略，支持带书签、有目录、分类专著条目、无目录脏扫描等所有场景。
3. **单一结构真相源**：以升级后的 `chapter_manifest.json` 作为下游所有模块（跨页拼接、翻译批次、排版发布）的唯一结构输入。

## 2. Stage 2：4 级可插拔逻辑切分路由

`scripts/chapter_split.py` 读取 Stage 1 的页级块数据与 `ocr_plan.json` 中的先验锚点，按置信度从高到低依次路由（支持 CLI 参数 `--strategy` 强制指定）：

### 策略 A：书签校准模式（Bookmark Calibration）
- **适用**：自带目录书签的电子书或精校扫描 PDF。
- **做法**：不信任书签的“整页”边界。以书签页码为中心，在前后 2 页窗口内检索与书签标题相似度最高的 `title` 块，将起点精确锁定为 `[page, block_idx]`。

### 策略 B：印刷目录锚定模式（TOC Anchoring）
- **适用**：无内置书签但前 20 页包含清晰目录的纸质扫描专著。
- **做法**：复用 `booklayout/contents.py` 解析目录项 `(title, printed_page)`；结合 `booklayout/furniture.py` 提取的页脚印刷页码计算分段偏移量，在预测物理页前后 5 页窗口内对齐正文 `title` 块。

### 策略 C：分类学条目与检索表模式（Taxon & Key Plugin）
- **适用**：动物志、植物志、分类专著、检索表（往往章内包含数十个物种记述，传统“章”粒度太粗）。
- **做法**：
  - 将 `taxadb/split.py` 与规则文件（如 `taxadb/rules/动物志.toml` 及可扩展的外文专著 TOML 规则）接入为二级切分插件，把长章节进一步拆分为独立的 `taxon_entry` 子节点。
  - 联动 `docstore/keyblocks.py` 与 `docstore/keys.py`，将分类检索表识别并标记为独立的 `key` 节点，严禁混入普通正文段落流。

### 策略 D：无目录 / 脏扫描兜底模式（Heading-Only LLM Clustering）
- **适用**：无书签、无目录、或目录严重缺损的期刊长文/影印古籍。
- **做法（极低 Token）**：
  1. **0 Token 本地初筛**：遍历所有页级 JSON，仅提取满足以下任一条件的短块：`layout_type == "title"`、字号大于全书正文中位数 1.15 倍、居中独立成行且长度小于 120 字符、或命中领域正则（`Chapter`、`Family`、`Genus`、`Key to`）。
  2. **页眉突变辅助信号**：调用 `booklayout/furniture.py` 检测奇偶页页眉（Running Header）文本发生切换的页码，作为强章节边界提示。
  3. **清单级轻量 LLM 聚类**：将压缩后的数百行候选清单一次发给轻量模型，输出层级树并剔除误判的图注/页眉。

## 3. 升级版 `chapter_manifest.json` 契约

在 `scripts/chapter_manifest.py` 中统一以下结构，通过 `node_type` 实现下游零硬编码分流：

```json
{
  "schema_version": "2.0",
  "book_id": "imajima_2003",
  "split_strategy": "bookmark_calibrated+taxadb_plugin",
  "nodes": [
    {
      "id": "ch03",
      "parent_id": null,
      "level": 1,
      "node_type": "chapter",
      "title": "Family Nereididae Johnston, 1865",
      "start": { "page": 50, "block": 1 },
      "end": { "page": 118, "block": 7 },
      "translate_policy": "translate",
      "split_source": "bookmark_calibrated",
      "confidence": 0.98
    },
    {
      "id": "ch03_key01",
      "parent_id": "ch03",
      "level": 2,
      "node_type": "key",
      "title": "Key to genera of Nereididae from Japan",
      "start": { "page": 51, "block": 2 },
      "end": { "page": 53, "block": 9 },
      "translate_policy": "translate_key_strict",
      "split_source": "docstore_keyblocks",
      "confidence": 0.95
    },
    {
      "id": "ch03_sp001",
      "parent_id": "ch03",
      "level": 2,
      "node_type": "taxon_entry",
      "title": "Namalycastis abiuma (Grube, 1872)",
      "start": { "page": 54, "block": 0 },
      "end": { "page": 56, "block": 4 },
      "translate_policy": "translate_taxon",
      "split_source": "taxadb_rule",
      "confidence": 0.96
    },
    {
      "id": "back_refs",
      "parent_id": null,
      "level": 1,
      "node_type": "references",
      "title": "References",
      "start": { "page": 370, "block": 0 },
      "end": { "page": 402, "block": 12 },
      "translate_policy": "skip_keep_original",
      "split_source": "bookmark_calibrated",
      "confidence": 0.99
    }
  ]
}
```

### `node_type` 下游分流规则

| `node_type` | 跨页断行拼接 | 翻译与质检管线 | 默认翻译策略 |
|---|---|---|---|
| `chapter` / `section` | 开启正文跨页拼接 | 标准翻译 + `transqa` | `translate` |
| `taxon_entry` | 仅在同级记述段内拼接 | 对接 `transqa/taxoblocks.py`、`species_format.py`、`taxoformat.py` | `translate_taxon` |
| `key` | **禁止普通正文合并** | 直通 `docstore/keys.py`、`booklayout/keymodel.py`、`keyalign.py` | `translate_key_strict` |
| `figure_plate` | 不合并 | 仅抽图与图注（`split_figures.py`） | `caption_only` |
| `references` / `index` | 按条目保持换行 | 跳过 LLM 翻译，节省大量 Token | `skip_keep_original` |

## 4. 强制检查点（`split_check.py` Gate）

在进入 Stage 3 与耗费 Token 的翻译之前，`scripts/split_check.py` 作为强闸门自动校验以下项目：
1. **块覆盖完整性**：校验所有正文块是否被单调、无重叠、无遗漏地归属到某个逻辑节点（显式标记跳过的页眉/页脚/空白页除外）。
2. **异常粒度预警**：单叶子节点字符数过高时提示启用二级切分；过短时提示可能误切了孤立页眉或图注。
3. **检索表完整性**：结合 `docstore/keyblocks.py` 验证检索表是否被章节边界拦腰切断。
4. **人机协同预览（Human-in-the-Loop）**：自动渲染一份轻量 Markdown 目录树预览（标注每个节点的 `[page, block]`、置信度与首行 30 字摘要）。人工只需花半分钟修正低置信度节点坐标，无需重跑 OCR 即可进入下一步。

## 5. Stage 3：切分后单元重组与逻辑批处理

严格锁定执行顺序为：**先按块级边界切出单元，再在单元内部做清洗与拼接**：
1. **剥离版面装饰**：在每个逻辑单元内部剔除 `header` / `footer`（`booklayout/furniture.py`）。
2. **图文分离**：提取单元内的图片对象与图注（`scripts/split_figures.py`、`booklayout/pdffigures.py`），在正文中留下稳定引用 ID（如 `fig_004`）。
3. **单元内跨页拼接**：仅在单元内部对连续正文块运行 `scripts/join_page_breaks.py`，杜绝“上一章末段误拼下一章标题”或“检索表条目被粘连”。
4. **逻辑批处理派发**：`scripts/plan_batches.py` 与 `scripts/run_batches.py` 直接消费单元 JSON，按 `node_type` 路由给 `auto_translate.py` / `direct_mode.py` / `fast_book.py`，并写入中心化 JSON 内容库（见文档 03）。
