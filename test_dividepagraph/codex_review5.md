### 新发现的实质问题

1. `booklayout/cli.py:49–51` — 高 — 固定临时名可移走原件。内存文件模拟中，`--aligned r.json.tmp --report r.json` 遇 v2 冲突返回 1，但写报告时对齐文件已被截断并改名，原路径消失 — 在目标目录排他创建唯一临时文件，只替换本次写入的目标。
2. `booklayout/cli.py:1203–1208,1219` — 高 — 路径检查只保护 `--report`；`--out` 与 `--patch` 同路径时，成功写回会把补丁替换为对齐 JSON，模拟中返回 0 — 写前拒绝输出与补丁指向同一文件，保留原地更新对齐文件的用法。
3. `booklayout/cli.py:1201,1219` — 高 — 两个进程可读入同一份对齐文件，分别修改不同块；即使两次替换先后成功，后写入的整份旧快照仍会抹掉先提交的译文 — 原地更新时将读取、校验、替换置于同一文件锁内，或在锁内核对快照版本后提交。
4. `booklayout/blockid.py:130–134` — 高 — 实际块按逻辑页排除，预期块按源页排除。若第 1 页应含来自第 2 页的续块 `B`，第 2 页逻辑页登记跳过，删掉 `B` 后，即使提供含 `B` 的完整源清单也得到 `ok=True` — 在清单中同时保留逻辑归属和源块标识，两侧按同一组明确排除的块比较。
5. `booklayout/blockid.py:81–88` — 高 — 新表目标 ID 未校验唯一。旧表只有 `A`，新表的 `A`、`B` 共用 ID `x`，实测返回 `旧A→x` 且无歧义；后续按 ID 取块可定位到 `B` — 先统计全部新块 ID，禁止将任何旧块映射到重复或无效目标 ID。
6. `booklayout/normalize.py:1884,1893–1897` — 高 — 数据块和补丁同时缺少 `block_id` 时，两者以 `None` 命中。实测 v2 补丁只给正确源哈希和 `remove:true` 就能删除无 ID 块 — 建索引和读取补丁时分别校验非空字符串 ID，任何缺失均拒绝应用。
7. `booklayout/normalize.py:1906–1910` — 高 — `remove` 按真值解释。实测带正确哈希、`"remove":"false"` 和新译文的 v2 补丁直接删块，并报告成功 — 要求 `remove` 为 JSON 布尔值，并拒绝删除与字段更新混用。
8. `booklayout/normalize.py:1912–1917` — 高 — 未识别的编辑仍记入 `applied`。实测将 `translation` 误写为 `translations`，v2 返回已应用，译文没有写入；空译块可因此被当作已补译 — 应用前校验字段名，并要求每条编辑至少包含一个有效操作。
9. `booklayout/normalize.py:1892–1918` — 高 — 直接调用 `apply_block_edits` 时，v2 批次前项成功、后项 `missing` 或 `stale`，传入对象已被部分修改。CLI 的拒写只能保护该次文件输出，库调用者继续保存对象就会提交半批修改 — 默认先验证整批再修改对象，将部分应用设为显式参数。
10. `booklayout/cli.py:51,1208` — 高 — `--aligned` 是符号链接且原地更新时，读取跟随链接，`replace` 却会用普通文件替换链接本身。CLI 可返回成功，而其他入口读取的真实对齐文件仍保留旧译文 — 读取和提交使用同一个已解析的目标路径，保留原链接。
