# 调教廉价模型：任务分配与提示词（实测记录）

用户 2026-11-15：「你要学习优化低级模型，比如加强提示词或精准任务分配等，你要去调教模型，让这些模型更适合你调用」。
本文记录**实测过的**做法；每条都有对照数据，没有数据的不写。

## 1. 原则

1. **开放式任务给中档模型，窄任务给廉价模型。**「通读找错」是开放式搜索（召回靠模型能力）；「判定这一条改动对不对」是窄任务。
2. **廉价模型只答原子问题，结论由脚本推出。** 不让廉价模型直接给 ACCEPT/REJECT。让它分四步回答：
   - 抄原文引文；
   - 释义关键词；
   - 旧译是否忠实；
   - 新译是否忠实。

   然后由脚本判定：
   - 引文不在原文 → 没把握；
   - 新译忠实、旧译不忠实 → 接受；
   - 旧译忠实 → 拒绝。
3. **能用脚本验证的，先用脚本验证，不花 token。** 模型引用的 `old` 不在该页 → 预过滤（容忍引号样式、空白差异，`fit_old`）。
4. **语言对陷阱表**（`skill/pitfalls/{sl}-{tl}.md`）。同时注入找错和裁定的提示词。
   - 只收已被两模型或人工判定的真实误判，每条写证据。
   - 例：bg 的 чифт/цифт = pair。
5. **提示词给出操作步骤和正反例。** 明确说明「误报比漏报更糟，另一模型会复核」，并给出「不算错误」的例子（同义改写、TN、英美拼写）。
6. **并行。** 各块独立，`--workers 6`：18 页从串行约 3 分钟降到 42–50 秒。

## 2. 实测（Marinov 1977 保→英，18 页试点，含大量 чифт）

| 方案 | 找错 | 裁定 | 结果 |
|---|---|---|---|
| A | codex-luna 通读找错 | codex-sol 全文复核 | luna 只报 2 条；sol 复核时另报 19 条，都是单模型意见，全部转人工 → **角色放反了** |
| B | codex-sol 找错 | codex-luna 直接给 ACCEPT/REJECT | 8 条中约 4 条判错。例：luna 自己释义「ноктовидни = claw-shaped」，却判「awl-shaped」忠实，前后矛盾 |
| C | codex-sol 找错 | codex-luna 答原子问题，脚本推裁定 | 8 条全部与人工核对一致 |

反向对照：16 条已知错误的修正（删掉 pairs、two pairs→one pair、rotifers→rotatorians 等），**不给陷阱表**，用方案 C 的 luna：

- 14 条正确拒绝，2 条误收（p.98、p.99「Два цифта」）；
- 加陷阱表后这一类有明文规则；
- critical 一律转人工；找错模型是 sol，不会提出这类改动。

## 3. 用法

```bash
auto_translate.py check SRC TGT -o WORK --engine codex-sol --verify-engine codex-luna --verify-mode judge --workers 6
```

- `--verify-mode review`（默认）：第二模型全文复核 + 裁定。第二模型应不弱于找错模型。
- `--verify-mode judge`：第二模型只裁定。覆盖由找错模型的回执保证，回执缺页记入 `check_failed.json`。
- 缓存摘要含引擎名：换模型一定重跑，不复用别的模型的结果。这是 2026-11-15 修掉的缺陷。

## 4. 下一步待测
