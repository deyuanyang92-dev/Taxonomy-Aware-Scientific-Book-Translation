写入者标记：`--by cursor`（或环境变量 `DOCSTORE_AGENT=cursor`）。只用中文或英文写作。

## 背景（先读，不要跳过）
- 工作区入口：`/mnt/p/翻译-译作/AGENTS.md`（第 0、0b、3 节）。
- 本仓库：`AGENTS.md`、`docs/architecture.md`、`docs/workflow.md`，已有试点 `docs/ocr_consensus_pilot.md` 和 `docs/ocr_consensus_pilot_metrics.json`（后者工作区有未提交改动，是别人的进行中工作：不要还原、不要覆盖）。
- 现有命令：`docstore text / consensus / quality / verify / page / status`。先读它们的实现，再动手。
- 现状（`docstore status`，2026-11-11）：41 份资料 16105 页。text_layer 8293，ocr_verified 278，ocr_sampled 2638，ocr_raw 4843（未核），blank 53。引擎有 RapidOCR/PP-OCRv3、glm-5.3-flash-local（视觉模型转录）、codex。
- 用途：从这些资料抽术语（学名、中文科属名、形态术语、页码）。最怕的错误：生僻字漏识（如「𧍒」「螠」）、学名拉丁字母错、数字和页码错、双栏串行、整行漏掉。

## 目标
1. **先量化，后优化**：用已校正的 278 页（ocr_verified）作金标准，计算各引擎、各资料类型的字符错误率（CER），并单独统计：拉丁学名、数字、生僻字（CJK 扩展区）、漏行。结果写入 `docs/ocr_accuracy_baseline.md`（附数据 json）。金标准不足以覆盖的资料类型要写明。
2. **调研**：比较可行的提准手段，每条要有依据（本地实测数据，或论文、官方文档链接）。至少考虑：
   - 多引擎共识（RapidOCR 与视觉模型逐字对齐投票）、提高 DPI、去噪和二值化、版面分析（双栏排序）；
   - 置信度与异常信号：低置信字符、乱码率、非常用字比例、行数和字数相对页面图像的异常、拉丁词不在已知学名表（yiku 术语库 `~/.yiku/yiku.db`、WoRMS 名录）中、中文科属名不在 yiku 中；
   - 页码连续性、目录与正文交叉核对。
3. **实现自动质控**：在 docstore 里加 `docstore qc`（或扩展 `quality`），为每页计算风险分，并按规则分流：
   - 自动通过：写入质控等级，并记录依据；
   - 自动重做：换引擎、提高 DPI 或用视觉模型重转录，再用共识合并；
   - 人工队列：生成抽查单（页图路径 + 可疑字符位置）。
   要求可断点续跑、只增不删：旧版本保留为 alt，每次改动写 `--by` 和原因。阈值写在配置文件里，并用金标准标定：给出在金标准上的查全率和误报率。
4. **测试**：`python3 -m pytest -q`、`ruff check`、`mypy` 必须通过；新功能要有测试。
5. **试点**：先在 2 份资料上跑完整流程（建议「杨德渐2006」和「刘瑞玉2008名录」），报告分流比例、抽查结果、耗时。全库铺开前停下，等用户确认。
