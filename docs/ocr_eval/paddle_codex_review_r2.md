1. **高｜`docstore/textify.py:311`**　显式指定 `["paddle_vl", "tesseract"]` 时，云成功页直接 `save`，跳过 Tesseract，但共识版本仍标记两个引擎。应把云结果作为首个读数，执行其余显式引擎后再投票，按实际参与者署名。
12. **中｜`docstore/engines/paddle_vl.py:384`**　拆块左半已成功、右半命中配额时，异常使左半的 `ok` 无法返回，外层把原块所有页都标为配额失败。应保留已通过的子块结果，仅将未完成页转入降级。
13. **中｜`docstore/engines/paddle_vl.py:430`**　所有块预先入队，配置错误按提交顺序读取，线程池退出时还会等待排队任务跑完。首块返回 401 后，其余块仍可继续提交。应在工作线程发现配置错误时立即广播停止、取消待执行任务并上抛。
14. **中｜`docstore/engines/paddle_vl.py:337`**　下载返回 429 或 401 一律按暂时错误处理，随后可能重提任务，绕过 §3.3 的配额与配置错误分类。应对下载失败应用 HTTP 错误分类，并测试下载阶段的 429、401。
15. **中｜`docstore/engines/paddle_vl.py:319`**　先接受 `done`，后检查超时，轮询退避也不受截止时间约束；超过块总等待上限仍可判成功。应使用统一截止时间约束请求和退避，并在接受结果前复查。
16. **中｜`docstore/engines/paddle_vl.py:228`**　已复现合法 JSON 字符串中的 U+2028 被 `splitlines()` 拆成两条残缺记录，使有效 OCR 结果整块失败。应只按 JSONL 的 LF 分行，兼容 CRLF。
17. **中｜`docstore/textify.py:323`**　降级成功后的 `save()` 没有收到云失败原因，进程池路径亦同，§3.0 要求的原因只留在调用返回值。应将该页原因写入实际降级版本的 `extra`，并从库中回读验证。
18. **低｜`tests/test_paddle_vl.py:509`、`:518`**　`assert fs.posts` 在仅有批量请求时也成立；搜索整页序列化字符串也无法验证块号、具体值或元数据所属版本。应断言上传页序列为 `[[1,2,3],[2]]`，并定位 `paddle_vl` 版本逐字段核对。
