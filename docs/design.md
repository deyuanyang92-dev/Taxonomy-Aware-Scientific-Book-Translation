# 顶层设计：分类学知识底座与专著翻译系统

版本 2026-11-10。本文只讲结构和原则，一页读完；操作细则见 `方案.md`，规则见 skill `yzz-translate`，入口见 `AGENTS.md`。

---

## 1. 定位

这不是一个「翻译工具」，而是**一个专业知识底座，加上建在它上面的几条生产线**。翻译只是第一条生产线。

目标是**通用的专业翻译系统**（用户 2026-11-10）：核心与领域无关，专业知识放在「领域包」里。分类学（多毛类、星虫、螠虫、蛭类等全部类群，同一标准）是第一个领域包；进化生物学、科学史已有雏形；以后加新领域只需加领域包和资料，不改核心。

三样产出：
1. **译著**：Rouse 2022、Handbook 等专著的中文版（学习交流用）。
2. **术语库**：每个术语、类群名的中文定名都有出处，可持续积累。
3. **分类数据库**：志书、专著、论文里的物种记述、名称用法、异名、分布，结构化、可回原页。

同一份资料学一次，三样产出都受益；用户每加入一份权威资料，系统就变准一点。

---

## 2. 设计原则

1. **证据先于结论**：任何译名、数据都带出处（书名 + 页码或条目编号）；查不到就标「暂定」，不编造。
2. **单一主库**：每类数据只有一个存放处，其余都是导出视图。
3. **状态分级**：数据和译文都带核对等级，低等级不得用于高要求的用途。
4. **改动只走一个入口**：译文的任何修改（含批量替换）都经问题单和闸口，留记录、可回退。
5. **原文不可侵犯**：学名、命名人、年份、数字、检索表逻辑、异名历史照原书；原书错误只加注，不径改。
6. **错误回流**：每个错误要回答「下次由哪一步自动拦住」，并变成一条自动检查。
7. **贵的模型只做判断**：能用脚本就不用模型，能用小模型就不用大模型；主会话和用户只看裁定、抽查和设计。
8. **任何模型可接手**：进度写在文件里，不写在对话里。

## 3. 架构：四层

```
┌──────────────────────────────────────────────────────────────────────┐
│ ④ 出口      译著（Word/PDF）  名录  物种汇编  新种稿与审稿的资料支持 │
├──────────────────────────────────────────────────────────────────────┤
│ ③ 生产线    翻译线：术语→初译→译审→分类学验证→表述→裁定→排版      │
│             数据线：记述切分→名称用法→对照 WoRMS→名录导出           │
├──────────────────────────────────────────────────────────────────────┤
│ ② 知识底座  术语库 yiku        定名、出处、状态（唯一术语主库）      │
│             分类数据库 taxa    书目 / 物种记述 / 名称用法 / 页文本    │
│             写作规范           志书表述规律、总论概念、陷阱表        │
├──────────────────────────────────────────────────────────────────────┤
│ ① 资料层    动物志、近海1988、名录、学位论文、经典译作（本地 PDF）   │
│             名词委术语在线、ANNiKEY、WoRMS、物种名录（外部，按需查） │
└──────────────────────────────────────────────────────────────────────┘
        ↑ 反馈回流：读者意见、外部审查、抽查 → 规则 / 陷阱表 / 术语库
```

层间规则：上层只读下层；下层不知道上层。翻译线出问题不会弄坏数据库，数据库重建不会改动译文。

### 3.1 核心与领域包

| | 核心（所有领域共用） | 领域包（每个领域一份） |
|---|---|---|
| 规则 | 忠实、数字专名保护、改动走闸口、异模型译审、抽查 | 依据次序、专名惯例、写作规范、陷阱表 |
| 数据 | 术语库结构、页文本、段对齐、状态、问题单 | 领域数据表（分类学：物种记述、名称用法；其他领域按需，如法规条文、药物名） |
| 验证 | 数字、引文、图号、结构计数 | 领域验证器（分类学：学名、检索表、异名、分布） |
| 外部资料 | 名词委术语在线（各学科名词） | 领域资料（分类学：志书、名录、WoRMS、ANNiKEY） |

新增一个领域 = 一份 `domains/<领域>.md` + 依据次序 + 资料登记 +（可选）领域数据表与验证器。分类学是最复杂的一个，先把它做透，再抽象出通用部分。

## 4. 数据与状态

| 数据 | 主库 | 核对等级（低 → 高） |
|---|---|---|
| 术语、类群名 | yiku | 候选 → 已证（原页确有此字）→ 已核（按依据次序定名）；另有「暂定」 |
| 页文本、物种记述、名称用法 | taxa.sqlite（含页文本库） | 机器初识 → 已抽查 → 关键字段已核 → 全文已核 |
| 译文 | `<书>/译文/` | 初译 → 已译审（异模型）→ 已验证 → 已裁定 → 已发布 |
| 问题、裁定、验证、对齐 | `<书>/核译/` | 每条挂原文段号 |
| 进度 | `<书>/状态.json` | 每章 × 每模块 |
| 规则、陷阱 | skill `yzz-translate` | 陷阱表机器可读 |

使用门槛：
- 进术语表、指导翻译：术语须「已核」或明确标「暂定」。
- 用于名录、描述提取：记述的学名、命名人、年份、数字须「关键字段已核」。
- 对外发布：译文须过验证与裁定，交付检查全过。

依据次序（定名用）：用户核定 > 志书正式记述 > 近海1988 > 名录 > 名词委（志书没有时）> 专题学位论文 > 暂定（WoRMS 派生、词源）。详见 `方案.md` 第 3 节。

## 4a. 资料持续入库（参考数据集会定期增加，用户 2026-11-10）

用户随时往 `参考资料/`（志书、名录、专著、论文）或 `一些经典译作/`（译本、原著、中文论著）放新书。系统要做到：**放进去 → 一条命令 → 自动入库、分级、抽取、排队待核**，不靠人记得哪本做到哪。

### 登记表（唯一进度来源）
`参考资料/资料登记.tsv`，每份文件一行，按 sha256 识别（改名不重复登记，内容变了视为新版本）：

| 列 | 说明 |
|---|---|
| key | 来源代号（如 `Nei2000_zh`） |
| path、sha256、pages | 文件信息 |
| kind | 志书 / 名录 / 专著 / 学位论文 / 译本 / 英文原著 / 中文论著 |
| lang、pair | 语言；对照书互指 key（如 `Nei2000_en` ↔ `Nei2000_zh`） |
| domain | 分类学 / 分子系统学 / 进化生物学 / 科学史 / 植物系统学 …（决定术语入哪个领域） |
| tier | 依据等级（见第 4 节） |
| 各阶段状态 | 文本化、质量、抽取、核验、文风 —— 未做 / 进行中 / 完成 / 需重做 |

### 流水线（每阶段可重入，按登记表续跑）

| 阶段 | 做什么 | 谁 | 通过标准 |
|---|---|---|---|
| 0 扫描 | 找出新文件与变更文件，追加登记行；kind、domain、pair 由文件名和前几页初判，主会话确认 | 脚本 + 主会话一眼 | 每份新文件都有一行 |
| 1 文本化 | 有文本层直接取；扫描件 RapidOCR 300 dpi 并行；逐页记方法与质量分 | 脚本 | 每页有文本或标为空白 |
| 2 质量 | 低分页、乱码页、生僻字缺失页列清单；按页抽样看图核对 | 脚本 + haiku（看图） | 抽样错字率达标，或已列入待校 |
| 3 抽取 | 志书/名录/论文 → 物种记述、名称用法、术语候选、描述段落；对照书 → 按章对齐抽译者用字（`yiku pair`）；中文论著/译本 → 「中文（English）」（`yiku paren`） | 脚本 + haiku/sonnet | 产物带来源与页码，一律「候选」 |
| 4 核验 | 候选术语回原页确认有此字 → 「已证」；冲突进冲突表 | 脚本 | — |
| 5 学写法 | 从描述段落、译本归纳表述规律，带计数与例句 | sonnet 归纳，主会话核后入领域包 | 每条规律有原文例句和计数 |
| 6 报告 | 本次新增：页数、OCR 质量、候选数、冲突数、待裁定清单 | 脚本 | 用户一页看完 |

### 规则
- 新资料只产出「候选」；进入定名须按依据次序裁定，用户核定优先。
- 领域隔离：植物学书里的「居群」不进动物学定名；老译本（如胡先骕译塔赫他间）的用字标年代，作为历史用法，不直接定名。
- 扫描件 OCR 的「0 次」不等于原书没有；生僻字回原页。
- 不删除原件；新版本与旧版本并存，登记表指向当前版本。

## 5. 模块

每个模块只通过文件交接，输入、输出、通过标准固定，可单独换模型、单独重做（详表见 `方案.md` 第 2.1 节）。

| 线 | 模块 | 通过标准（一句话） |
|---|---|---|
| 学习 | 登记 → 文本化 → 记述切分 → 抽术语 → 核验定名 → 归纳写法 | 产物带核对等级；归纳的规律经原页或计数核实 |
| 翻译 | M1 解析 → M2 术语 → M3 试译样章 → M4 初译 → M5 异模型译审 → M6 分类学验证 → M7 志书表述 → M8 裁定 → M9 排版校样 → M10 回流 | 样章抽查错误率 ≤ 5% 才铺开；每条问题有裁定与依据 |
| 数据 | 记述 → 名称用法 → WoRMS 对照 → 名录 / 汇编导出 | 关键字段对原页核过；原样拼写不改 |

三层分离（新书起执行）：**译文**（干净文本）｜**标注**（中文名加注、暂定标记、英文括注，排版时生成）｜**排版**。改标注规则只需重排，不动译文。

## 6. 角色与模型分配（用户 2026-11-10 定）

主会话（最强模型，Fable）只做两件事：**顾问**和**编排**。不亲手跑流水线、不查文件、不调脚本。

| 层级 | 做什么 | 谁 |
|---|---|---|
| 脚本 | OCR、切分、替换闸口、验证、一致性、排版、量页 | 无模型成本 |
| 轻量 | 跑现成流水线并汇报、看图核对字段、机械抽取、格式检查、按模板填表 | haiku |
| 中等 | 初译、译审（与初译不同模型）、查证、归纳、脚本调试、排版故障排查 | sonnet、Codex、DeepSeek |
| 较强 | 多文件代码实现与重构、中等模型失败一次的调试、复杂数据清洗规则 | opus |
| 顾问/编排 | 顶层设计、写任务书、分派、审结果、裁定、抽查、疑难判断 | 主会话（Fable） |
| 用户 | 定依据次序、裁冲突与暂定名、终审 | — |

**分派规则**
1. 每项工作先问：能脚本化吗？不能，最小够用的模型是谁？
2. 任务书写清：目标、输入输出路径、通过标准、已知的坑、禁止事项（不得再派子任务、不得改主库、每步写盘）。
3. **升级**：子代理失败一次，或自报「拿不准」→ 升一级模型重做；两级都失败 → 交主会话。
4. **顾问制**：子代理遇到任务书没覆盖的判断（译名取舍、规则冲突、数据与原页不符），**停下来写求助**（问题 + 已查到的证据 + 备选方案），不得猜；主会话答复后继续。
5. 主会话只读子代理的结论和抽样，不重读它读过的全文；抽查用脚本或局部裁图。
6. 真正需要最强模型的事：设计与规则变更、有争议的裁定、子代理两次失败的难题、对外定稿前的终审。其余一律下放。

## 7. 质量体系

三道防线：
1. **事前**：术语表注入、志书例句、领域规则、陷阱表。
2. **事中**：异模型译审（正反两遍、数字专名、结构计数）；分类学验证脚本；志书表述核对。
3. **事后**：主会话裁定（用字问题先查志书）；每批随机抽 20 条；读者与外部审查回流。

度量（每次发布记录，用来判断系统是否在变好）：

| 指标 | 现状（2026-11-10，Rouse） | 目标 |
|---|---|---|
| 术语有可靠出处的比例 | 372 / 593（63%） | ≥ 95%，其余全部标暂定 |
| 经异模型逐句译审的章 | 11 / 79 | 79 / 79 |
| 验证脚本未处理报警 | 引文 27 条 | 0 |
| 抽查错误率 | 未系统做 | ≤ 5% |
| 物种记述关键字段已核 | 0（卷33 试点中） | 多毛类五本志书 100% |

## 8. 与 yzz 分类工作流的关系

- **oworms**：WoRMS 的唯一接口；有效名、异名、模式属。WoRMS 相关新功能写进 oworms。
- **yzz-compilation**：分类数据库用同一套 `work / treatment / name_usage` 结构，志书记述可直接供物种汇编使用。
- **yzz-zootaxa、yzz-review**：写新种稿、审稿时从分类数据库取中文文献里的描述、异名、分布。
- **yzz-zh**：所有交付文件的最终检查。
