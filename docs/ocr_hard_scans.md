# 难扫描件 OCR 优化（ppocr 引擎，2026-11-15）

评测脚本与金标准：`/mnt/p/翻译-译作/日本-imajima/bench/`（`quality.py`、`gold/`，结果 `quality_result*.md`）。
引擎：PP-OCRv5 server（`docstore/engines/ppocr.py` + `ppocr_worker.py`），GPU（GTX 1660 SUPER，paddlepaddle-gpu 3.3.1）。

## 测试集

- 真实页 14：`/root/ocr_eval` 评测集中 glm/人工核对过的 12 页（动物志、名录、专著扫描）+ Imajima 日文 2 页（逐字对页图核对）。
  注意：近海1988 p.80/p.150 是图示检索表，glm 金标准本身有错（「吓触几前叫」），这两页数字不可信。
- 人工劣化 20：Imajima 2 页 × 模糊、噪点、低对比+不均匀光照、倾斜 2°、低分辨率、JPEG q12、透印（强/弱）、老扫描（轻/重）。
- 指标：CER（去空白去标点按序比对）与字符袋误差（不受读序影响）。样本小，是强信号不是定论。

## 结果（平均 CER）

| 方法 | 真实页（14） | 劣化页（20） | 结论 |
|---|---|---|---|
| base（200 dpi 直接识别） | 0.079 | 0.137 | |
| 全页增强（背景归一+去噪+拉伸） | 0.058 | 0.252 | 只对低分辨率有利，其余变差，不用 |
| 二值化（背景归一+Otsu） | 0.060 | 0.078 | 透印 41%→0.5%，但模糊页 0.9%→6.8%，不能一律开 |
| 纠斜（阈值 0.3°） | — | — | 误纠正常页（刘瑞玉 p.106 0.9%→3.1%）；阈值改 0.8° |
| 低置信行放大重识 | 0.080 | 0.134 | 收益小，不用 |
| 非局部均值降噪（作自适应候选） | — | 0.052（对比 0.051） | 无收益且会被误选，不用 |
| **自适应（采用）** | **0.079（不变）** | **0.039** | 见下 |

自适应 = 平均置信度 < 0.93 且字数 ≥ 80 时再用二值化图识别，「置信度×字数」更高**且**平均置信度不降（≤0.01）才采用；
倾角 > 0.8° 纠斜重识，纠斜后平均置信度降 >0.02 则退回。
（初版只看「置信度×字数」，在插图页上偏向多检出的乱码：Imajima2001 p.78 字数 5→49、置信 0.68→0.41 仍被选中；
三卷 58 页触发二值化，加条件后 9 页。）纠斜实例：Imajima2009 p.274 倾斜约 1° 导致双栏判断失败、左右栏行被拼接，纠斜后恢复。
另加整页旋转判断：竖长框 ≥ 4 成且平均置信度 < 0.75 时试 ±90°（Imajima2001 横排站位表 p.123/343：置信度 0.26→0.98）。

## 其他已确证的坑

- docstore 多进程（--workers ≥2）给子进程设 OMP_THREAD_LIMIT，paddle 继承后检测漏行（Imajima2007 p.22：45→32 行；
  171 页漏 26% 行框）。ppocr.py 已在子进程环境里去掉这些变量。
- 200 dpi 优于 300/400 dpi（日文 2 页实字错误 0.08%/1.1% vs 0.59%/1.4%）；300 dpi 常丢行末「な」。
- 乱码行过滤（cp932 字集）只能用于日文页；中文页用会丢简体字行。现按页内假名比例自动判断（DOCSTORE_PPOCR_LANG=auto）。
- 剩余弱项：重度老化（低对比+噪点+倾斜+透印）仍约 12–13%；生僻字（螠）偶尔漏识。

## 多引擎与大模型复核（2026-11-15，`bench/ensemble.py`、`bench/tiers*.py`）

同一行框裁图交多个识别器（行天然对齐）。24 页（真实 12 + 日文劣化 12）：

| 方法 | 真实页 | 劣化页 | 说明 |
|---|---|---|---|
| PP-OCRv5 server（现行） | 2.23% | 5.37% | |
| PP-OCRv5 mobile / RapidOCR / Tesseract | 2.96% / 11.5% / 16.3% | 5.32% / 39.3% / 23.4% | RapidOCR 不识假名 |
| 3–4 引擎逐行投票 | 2.18–2.24% | 5.17–5.33% | 几乎无收益（其他引擎弱，同源模型错处相关）|
| 争议行（server≠mobile 且置信 <0.97）交 Haiku 5.5 | 1.94% | 1.18% | 约 $0.0001/行 |
| 同上交 Sonnet 5.5（`--effort low`） | 1.96% | **0.79%** | 约 $0.0014/行 |
| Haiku→Sonnet 级联（Haiku 给出第三种读法或新汉字才升级） | 1.94% | 0.83% | 升级 55–62% 的争议行 |
| 本地 qwen2.5vl:3b（Ollama，9 页） | 0.70%* | 2.21%* | 劣于 Haiku；本机只能 CPU（模型估 10 GB）；把「疣」读成「犬」|

（* 只完成 9 页，与其他列不完全同批。）争议行占比：劣化页约 50%，清晰页约 16%。没有一页被复核改坏（护栏：
候选与任一 OCR 读法相似度 ≥60 才采用）。清晰页剩余错误不在争议行（多引擎同错或金标准问题），复核救不了。

调用方式：`claude -p --model sonnet|haiku --tools "" --setting-sources "" --strict-mcp-config --disable-slash-commands
--exclude-dynamic-system-prompt-sections --no-session-persistence --effort low --system-prompt <短提示>
--input-format stream-json`，一页的争议行（≤20 张裁图+两种 OCR 读法）一次请求。不加精简参数时
固定开销 2.35 万 token、一次 $0.10；加后 3 行 $0.0055。claude 自动更新时可执行文件会短暂缺失，调用须重试。

## auto 档：`scripts/ocr_review.py`（免费优先，最后才用模型）

```
/root/ocr_eval/venv_gpu/bin/python scripts/ocr_review.py <key> [--pages A-B] [--max-tier free|haiku|sonnet] [--dry]
```

| 级 | 做什么 | 依据（同上测试集，逐行对金标准） |
|---|---|---|
| 0 免费 | 争议行 = server≠mobile 且置信 <0.97 | 劣化页覆盖 99% 错字；置信度不能当门槛（0.95–0.97 档 server 也只对 69%） |
| 1 免费 | 同一行 8 个读法投票，≥7 票采用 | 7–8 票全对 89%（Haiku 81%）；5–6 票 76%、字符 n-gram 语言模型 38–59%，均不采用 |
| 2 Haiku | 其余争议行，原尺寸裁图，每次 ≤40 行 | 原尺寸与 2 倍放大准确率相当（Sonnet 84% vs 86%）；43 行一次 $0.0027，分 3 次 $0.0044，单行 $0.0002 |
| 2' Haiku 第二遍 | 同一批行无提示再读一遍；两遍一致即采用 | 第三读法行：一致 68%，其中 99% 正确；Haiku=OCR 读法的行：一致 82%，97% 正确 |
| 3 Sonnet | 只处理两遍 Haiku 不一致的行（约 1/4） | 合计正确率 97%/92%，高于「第三读法即交 Sonnet」(94%) 与直接用 Haiku(88%)；Sonnet 行数减半 |

试过但不采用的免费规则（逐行对金标准）：字形规则（简繁/新字体，8 行，对 62%）；一字之差按全书上下文片段
（能判 23%，对 82%，同批 Haiku 94%）；拉丁词表（能判 18%，对 43%）；字符 n-gram 语言模型（38–59%）；
按置信度跳过（0.95–0.97 档 server 只对 69%）。另：Haiku=某 OCR 读法的行全交 Sonnet 反而只对 78%（Haiku 88%）——Sonnet 并非越多越好。

端到端：Imajima2001 p.61 0.61%→0、Imajima2009 p.66 0.08%→0（两页共 $0.013）。改动逐行记 `_audit/ocr_review_<key>.jsonl`，
用量记 `_audit/ocr_review_usage.tsv`；新文本作主版本（producer `ppocr+review(...)`），旧版本保留在 alternates。

## NDLOCR-Lite 作免费第三票（2026-11-15，`bench/ndl_eval.py`）

NDLOCR-Lite（日本国立国会图书馆 NDL Lab，CC BY 4.0，https://github.com/ndl-lab/ndlocr-lite）的 PARSeq 行识别器，
与 PaddleOCR 不同源，CPU 即可（383 行 55 秒）。在同一批争议行上（逐行对金标准）：

| | 日文 317 行 | 中文 66 行 |
|---|---|---|
| server 原读法全对 | 32% | 59% |
| NDLOCR 单独 | 64% | 27% |
| Haiku | 85% | 76% |
| NDLOCR 与 server/mobile 之一一致（日 36%、中 27% 的行） | **97%** | 83% |
| 投票 ≥7 且 NDLOCR 同意 / 不同意 | 100%（15）/ 43%（14） | — |

规则（已进 `scripts/ocr_review.py`）：日文页先看 NDLOCR 一致（免费、与两遍 Haiku 一致同级），投票 ≥7 须 NDLOCR 同意；
中文页不用 NDLOCR。日文页约三分之一争议行因此不再调用模型。
