## 1. 目标：什么叫「准确」

1. **术语准**：每个术语有出处（书名 + 页码或名词委条目编号），同一术语按类群统一。
2. **句子忠实**：不漏、不增；数字、学名、引文、限定语（usually / only / may / presently）与原文一致。
3. **合乎中文分类学写法**：形态描述按志书惯例写（具/无 + 阿拉伯数字 + 量词、电报式短句、「长于」、「背侧」……），不是普通译文腔。

不能保证 100% 正确。做法是**每一步留证据，错误可测量、可回流**：抽查、外部审查和读者反馈发现的每类错误，都写进规则和陷阱表，下一轮自动检查。

### 2.1 模块（对应正规出版流程；参考 ISO 17100:2015 翻译服务、ISO 18587:2017 机器翻译译后编辑）

每个模块有固定的输入、输出、工具和通过标准，可以单独换模型或单独重做；模块之间只通过文件交接。

| 模块 | 对应出版环节 | 输入 → 输出 | 工具 | 通过标准 | 谁 |
|---|---|---|---|---|---|
| M0 立项 | 原著评估、版权与用途 | 原书 → `<书>/README.md`（版本、范围、用途） | — | 写明用途：**本工程为学习交流、非商业**；如转正式出版，须先取得译权许可 | 用户 |
| M1 解析 | Document Parser | PDF → `src_en/chNN.txt`、图库、参考文献 | extract.py、ocr_rapid.py、extract_figs.py、extract_refs.py | 章、图注、参考文献条数与原书一致 | 脚本 |
| M2 术语 | Terminology Manager | 原文 → 每章术语表、缺口、出处等级 | yiku、termonline_lookup.py、oworms、知识库 | 每个术语有出处等级；暂定登记 | 执行模型 + 主会话定名 |
| M3 试译样章 | 术语准备与试译 | 1–2 章 → 抽查记录 | 全流程跑一遍 | 抽查错误率 ≤ 5% 才铺开全书 | 主会话 + 用户 |
| M4 初译 | Translation | 原文 + 术语表 + 志书例句 → 译文 | run_batches.py | 无漏段（段号覆盖） | 模型 A |
| M5 双语译审 | Revision（另一人对照原文） | 原文 + 译文 → issues.jsonl | PROMPTS.md B 节；translation-quality-codex 段号 | 正反两遍、数字专名、结构计数 | 模型 B（≠ A） |
| M6 分类学验证 | Taxonomic Validator | 原文 + 译文 → `核译/验证/` | **taxon_validate.py**（学名、数字、引文、图号）；检索表/异名/分布人工逐项 | 每条自动报警已处理或说明 | 脚本 + 主会话 |
| M7 专业表述 | 学科编辑 | 形态描述、图注、术语释义 → issues.jsonl | domains/分类学.md 第 5 节、知识库例句 | 合乎志书写法 | 执行模型 + 主会话 |
| M8 专家裁定 | Subject-matter review | 全部 issues → 裁定记录 → 闸口 | apply_issues.py；裁定须查志书计数 | 每条有采纳/驳回与依据 | 主会话 + 用户 |
| M9 排版校样 | 编辑加工、校样 | 译文 → docx / PDF / 传播版 | build_docx、fig_defer、collect_pages、word_render | 目录页码、图注位置、空白页、交叉引用、zh check 全过 | 脚本 + 主会话目检 |
| M10 终审回流 | 终审与归档 | 读者意见、外部审查 → 规则、陷阱表、yiku | domains/分类学.md 第 6、7 节 | 每类错误写明「下次由哪一步拦住」 | 主会话 |

模块原则（采纳自外部建议并结合本工程经验）：
- **问题可追溯**：每条问题带原文行/页、译文原句、依据、类型。
- **术语审定有记录**：定名进 yiku，后续章节自动沿用；争议交用户，不由模型随机决定。
- **学名照原文**：依 ICZN 第 32 条，原始拼写原则上保留；原书笔误只加〔原文作…〕或〔原书如此〕，不径改（2026-11-10 验证脚本查出 1 处径改图号，已补注）。
- **分类学证据不因中文流畅而改变**：学名、命名人与年份、计数、比例、检索表分支、异名历史、分布记录逐项原样。

## 3. 依据次序（术语与类群名）

详表与外部链接见 `yzz-translate/TERMS.md`「依据优先级」和「外部资料」两节。概要：

| 级 | 来源 | 说明 |
|---|---|---|
| 0 | 用户核定（yiku `yzz_核定`） | 高于一切 |
| 1 | 《中国动物志》**正式记述该类群**的卷 | 卷9 表2、总论名单对别卷类群只是顺带列名，降到第 4 级之后 |
| 2 | 杨德渐、孙瑞平 1988；吴宝铃 1981 | |
| 3 | 刘瑞玉 2008《中国海洋生物名录》 | 名录自身印刷错误按志书改（如 Pilargis「毛虫属」→白毛虫属） |
| 4 | 名词委（术语在线：《动物学名词》2021 等） | **志书没有的术语才用**；志书有而不同时按志书，并在附录注名词委写法 |
| 5 | 专门研究该类群的学位论文 | 佐证或补缺，不单独推翻上级 |
| 6 | 《中国生物物种名录》2026 | 仅供参考（用户评价：整理一般） |
| — | 经典译作、名家论著 | 在其本领域（科学史、进化、物种概念）为最高级；与动物志冲突时交用户 |
| 暂定 | WoRMS 有效名/模式属派生 → 词源拟名 | 标「暂定名」，登记 `核译/uncertain_terms.tsv` |

规则补充：分类变动（亚科升科、属转移）沿用原中文名；一个中文名只对应一个拉丁名（新拟前查重名）；同一英文术语可按科不同（operculum、uncini、hood）。

## 4. 自动学习：加入一份新资料

用户放入新资料后，任何模型按此执行（`一些经典译作/AGENTS.md` 有逐步命令）：

1. **登记**：放 `参考资料/` 或 `一些经典译作/`，写 `来源.md`（书目、版本、文本层质量）。
2. **文本化**：有文本层用 `extract.py`；扫描本用 `ocr_rapid.py`（RapidOCR，不用 tesseract），多进程并行。
3. **入知识库**：`一些经典译作/知识库/scripts/build.py` → 整页文本、术语对（en–zh–页码）、描述段落分类（形态描述 / 分布生态 / 分类线索 / 异名）。
4. **抽术语**：对照书 `yiku pair`；中文论著 `yiku paren`；志书类群名用子代理逐条图像核对（先例：`terms/基准_动物志*.tsv`）。一律先入「候选」。
5. **核验与定名**：脚本核验原页确有此字；按第 3 节次序定名；冲突进冲突表。
6. **学写法**：从描述段落归纳志书表述规律，写进 `参考库/志书分类表述/文风笔记.md`；从总论整理概念体系，写进 `分类学基础_志书总论.md`。主会话**逐条用 OCR 计数和原页核过**才并入 `domains/分类学.md`。

学习成果的三种用途：定名（yiku）、检索例句（知识库）、写作规范（领域包）。

## 4b. 本地资料库的定位：分类学数据库，不只是术语来源（用户 2026-11-10）

本地化的志书、专著、论文同时服务四种用途，设计和质量要求按最严的用途来：

| 用途 | 需要什么 | 质量要求 |
|---|---|---|
| 术语定名 | 中英对照、页码 | 字形正确（生僻字回原页） |
| 表述学习 | 形态描述段落 | 段落完整 |
| **分类描述提取** | 每个种的完整记述：学名、命名人、异名列表、标本采集地、形态特征、地理分布、讨论、图号、页码 | **数字、学名、命名人、年份逐字可靠**（OCR 误识会直接变成错误数据） |
| **名录整理** | 每本书里出现的每个名称及其用法（有效名/异名/误定）、中文名、页码 | 名称完整、不漏种；与 WoRMS 有效名可对照 |

**数据层（与 yzz-compilation 对齐）**：
- `work`：书目（来源代号、书名、作者、年份、版本、PDF、页码偏移）。
- `treatment`：一个种（或属、科）在一本书里的一次记述：起止页、各分项原文（标本采集地/形态特征/地理分布/讨论/检索表）、图号；文本来源（文本层/OCR）与核对状态。
- `name_usage`：书中每次给出的名称：原样拼写、命名人、年份、中文名、用法类型（有效名/异名/误定/新组合/新记录）、所属 treatment、页码；可连到 oworms 的有效名（AphiaID）。
- `page`：整页文本与核对状态（已有）。术语、证据句、描述段落是从这几张表派生的视图。

**质量规则**：
1. 页面状态分三级：机器初识 → 已抽查 → 已逐页核对。**用于物种描述与名录的 treatment，其数字、学名、命名人、年份必须对原页核过**（可只核这些字段，正文其余可后核）。
2. 「OCR 0 次」不等于原书没有（如「稃」）；生僻字、数字、拉丁名的疑点一律回原页图像。
3. 原书印刷错误照录并标注，不改；与名录、WoRMS 的差异另列，不覆盖原文。
4. 每条数据保留来源与页码，可回原页。

**由此调整的优先级**：动物志卷5 蛭纲（265 页待校）和各书未核对的物种记述页，不再是「低优先」——凡要用于描述提取和名录的书，都要完成 treatment 切分与关键字段核对。执行说明见 `参考资料/_本地知识库/任务_分类数据层.md`。

## 5. 每章翻译（命令）

工程目录 `<书>/`：`src_en/` 原文、`译文/` 译文、`核译/` 问题与报告、`脚本/` 本书脚本。`S=~/.claude/skills/yzz-translate/scripts`。

1. **术语表**：`yiku table src_en/chNN.txt --domain 分类学 [--scope 类群] [--fallback 领域]`。表分 HARD（必用）与 SOFT（先判义项，附出处、层级、定义语境与中文用例；分类学书缺省回退到进化生物学）。初译者对 SOFT 术语的取舍记入 `term_decisions.jsonl`，主会话用 `yiku decide review/apply` 裁定写回。
2. **缺口**：本章有、库里没有的术语 → 按第 3 节查；名词委用 `python3 $S/termonline_lookup.py 缺口.tsv 结果.tsv`；类群名查 WoRMS（`oworms api`）。
3. **例句检索**（新）：本章形态段落涉及的结构（口前叶、疣足、刚毛……），从知识库检索 2–3 段志书同类描述，作为写法示例注入提示词。理由：MAPS（He et al., TACL 2024）表明先给模型关键词、主题和相关示例能改善译文；arXiv 2503.05010 专门比较「检索」与「生成」两种领域知识用法（结论未细读，未确证）。
4. **初译**（模型 A）：`python3 $S/run_batches.py <书> --mode translate --chapters chNN --engine <A> --domain 分类学`。注入 RULES、领域包、STYLE、术语表、例句。
5. **核译**（模型 B，必须不同于 A）：`plan_batches.py` → `run_batches.py --mode review --engine <B>`。按 `PROMPTS.md` B 节：正反两遍、数字专名、结构计数、severity/confidence 分级。长章可先用 translation-quality-codex 分块编段号（SKILL.md 第 4a 步，`--max-block-chars 1200`）。
6. **表述核译**：形态描述、图注、术语表释义对照 `domains/分类学.md` 第 5 节（type「表述」）。
7. **裁定**（主会话）：`domains/分类学.md` 第 7 节。用字意见须先查志书计数和例句；逐条写裁定记录；一类问题全书扫同类。
8. **分类学验证**：`python3 $S/taxon_validate.py <书> [chNN]` → `核译/验证/`。学名、数字、引文、图号原文有而译文缺的逐条列出；单位换算（3.5 亿年）、上标（10⁶）属正常，须人工逐条判。
9. **闸口**：`python3 $S/apply_issues.py <书> issues.jsonl`（先 `--dry`）；然后 `yiku check`、`drift_check.py`、`qa.py`。
10. **名称加注**（类群名、属种中文名）：`脚本/fill_family_names.py`、`脚本/annotate_names.py`；之后扫重复属名和嵌套括注。

### 6b. 全书模拟三审三校（`scripts/qa_run.py`，一条命令）

```bash
python3 scripts/qa_run.py <src.md> <tgt.md> -o <工作目录> --sl ja --tl en --glossary <术语表.tsv> --dry   # 只估算，不调模型
python3 scripts/qa_run.py <src.md> <tgt.md> -o <工作目录> --sl ja --tl en --glossary <术语表.tsv>         # 全流程
```

流程：确定性闸口 → 找错两遍（deepseek-flash）+ 复核 → 落实前护栏 → 段落对齐查漏译/凭空添加 → 落实后复检（新增阻断问题的页整页回滚）→ 人工小样包 → 报告。输入译文从不被覆盖；自动落实的改动写在 `qa_final.md`，逐条列在 `qa_applied.jsonl`。人工只看 `human_review_queue.csv`、`qa_sample.csv` 和 `qa_report.md`。
退出码：0 全部完成；1 有失败页或缺页；2 预算超限（已完成部分照常出报告）。预算上限默认是估算的 2 倍（`--budget-multiple N` 调倍数，`--budget-tokens` 直接指定）。每阶段写 `qa_state.json`，重跑跳过已完成的阶段，模型调用有缓存。DeepSeek 忙时由 `llm_engines` 自动等待。

**落实前护栏**（`transqa/guardrails.py`，不花 token；命中的改动转人工，不落实）：改动为空；译文里出现源语言文字；单处极性词互换（present/absent 等，词表 `skill/pitfalls/{sl}-{tl}.polarity.tsv`）而无原文原样引文；整句词序互换（同一批词换顺序，引文也不放行）；纯增补且增补的 ≥ 4 词连续片段在该页译文里已有。后两条来自 40 页验收里的两处真实错改（见下）。

**估算器校准**（`scripts/qa_estimate.py`，计费 token ＝ 输入 + 输出 + 缓存读取/50）。常量按冷启动（无前缀缓存）实测取，作上限：`CACHE_SHARE = {check 0.60, verify 0.88, align 0.87}`，`OVERHEAD_TOKENS_PER_CALL = {check 2480, verify 1200, align 530}`，`OUT_RATIO = {check 0.040, verify 0.102, align 0.023}`。同一份 40 页数据的实测与估算对照：

| 运行 | 实测计费 token | 估算 84,435 的偏差 |
|---|---|---|
| 冷启动（`cold`） | 82,305 | +2.6% |
| 植入译文（`seeded`） | 77,157 | +9% |
| 暖缓存（`clean2`） | 45,010 | +87%（高估，安全方向） |

DeepSeek 前缀缓存使同一输入的花费差近一倍；复核阶段在 1 万到 3.2 万之间浮动；找错阶段的固定开销随术语表大小变化。默认 2 倍上限覆盖了全部三次实测；暖缓存时上限约为实际花费的 3.7 倍，这是已知代价。

**40 页验收**（日语→英语，日本多毛类志书 40 页；样本小、植入偏机械、错改判读由模型对照原文完成，未经分类学家复核）：

- 植入基准（`scripts/bench/qa_seed.py` 植入、`qa_score.py` 严格按页内位置打分）：检出 28/30（数字 6/6、含义翻转 6/6、学名改拼 6/6、凭空添加 6/6、漏译 4/6；漏掉 p.326 与 p.162 各一处）。与 spec §4.1 的 V0∪V3 并集（23/28）在噪声（±3）内可比。自动落实 7 条（翻转 4 条里还原 3 条、添加 2/2），转人工 21 条。
- 干净基线（未植入）：转人工 16 条（找错 10 条，约 4 个真实缺陷：p.6 的「32」、「anterior end or」、检索表偶句编号等；对齐 6 条，其中 5 条是误报，译文里其实有该内容）。**「≤ 5 条/40 页」的验收标准按字面未达到**：主因是对齐阶段在干净译文上精确率低（闸口只核对引文确在原文里，不核对译文里是否缺该内容）。该阶段只转人工、不自动改，代价是人工多看几条，已列为遗留项。
- 自动落实的改动逐条对照原文：干净基线 10 条里有 2 条明确错改，均已加护栏并对已记录的改动重放确认被拦（p.286 把 notopodium↔neuropodium 整句互换，理由「後足葉＝neuropodium」不成立——原文是 postchaetal lobe，原译文本就错；p.14 把该页已有的「Arrangement of elytra varies among individuals」又补了一遍）。另有 p.109 凭空加「(a mark)」一条不改变含义，已放行，须在人工小样里留意。植入译文那次运行自动落实的 7 条里，p.224（把 postchaetal 写成 posterior）与 p.162（annulation）两条不够准确但没有翻转含义。
- 花费：三次完整运行均在预算上限内（见上表）。

**已知限制**：术语库没有「前足葉/後足葉＝prechaetal/postchaetal lobe」条目（p.286 错改的上游原因）；回执（模型声明已通读各页）的遵守率不够高，qa_run 不再把回执缺失当作硬失败，只在报告覆盖率里标「回执未确认」；植入选中了索引页 p.406，机械植入对索引页意义不大。

## 7. 出版（Word / PDF）

在书目录下（详见 `<书>/README.md`）：
1. `python3 脚本/build_docx.py 发布/v0.01/书名.docx`
2. 插图浮动（2–3 轮）：Word 渲染 → `python3 脚本/fig_defer.py 渲染.pdf` → 再 build（图放在首次引用处附近，放不下时让正文先排满，图落下一页页首）。
3. 目录量页：`C:/Python314/python.exe -X utf8 collect_pages.py 书.docx`（Word COM）→ 再 build。
4. `C:/Python314/python.exe -X utf8 word_render.py 书.docx` 导出 PDF/A（**不加 --toc**，曾卡死）。Windows 的 Python 一律加 `-X utf8`，否则打印生僻字（如 𧍒）会因 GBK 崩溃。
5. 传播版：`scripts/publish/share_pdf.sh 正式版.pdf`（Ghostscript，图像降到 120 dpi、JPEG 质量 72，字体仍全嵌入；Rouse 55 MB → 12 MB，图文清晰）。
6. `zh check` docx 与两个 PDF；脚本核目录页码、空白页、图注位置、插图数。
7. 成品发现个别错字时不必整本重排：`python3 -X utf8 scripts/publish/patch_release.py 书.docx 替换表.tsv`（旧→新定点替换，跨 run 拆开的也能改，逐条报告次数与未命中）；PDF 仅在新旧字数相同且新字字形已在嵌入字体子集里时原地改，否则按提示由改后 docx 用 word_render 重渲染。

版式约定：章首「中文章名 原书标题」一行；目录「章号 中文名 原文名」；不印 DOI 与原书页码；参考文献照录英文列附录；只保留一个发布版本，修订直接覆盖。

## 10. 从开源翻译流程学到的（2026-11-10 调研）

| 项目 | 做法 | 我们是否采纳 |
|---|---|---|

## 11. 软件设计（v2，2026-11-10 自审后重写）

### 11.1 自审：原设计（7 个子命令串脚本）的问题

原设计只是把现有脚本包一层命令，没有解决这两天实际暴露的结构性问题：

| # | 问题 | 实际出过的事 | 设计对策 |
|---|---|---|---|
| 1 | **数据多头存放**：同一术语存在 skill `terms/*.tsv`、yiku、书内 `术语库/`、两个知识库里 | 合并查名结果时覆盖了 `高阶元_核定.tsv` 里 29 条出处，靠 yiku 副本才恢复 | 每类数据只有一个主库（11.2），其余是导出视图 |
| 2 | **标注烤进译文**：中文属名、英文括注、「暂定名」直接写进 md | 「光缨鳃虫属光缨虫属」「（颚环（maxillary ring） maxillary ring）」；改一条括注规则要全书正则替换 | 译文保持干净，标注在排版时按术语库生成（11.3） |
| 3 | **批量替换绕过闸口**：规则写的是「一切改动走 issues + 闸口」，但全书术语替换是直接正则改的 | 名词委 33 条、背外侧 15 处等都是直接改，靠事后抽查；「垫」这类多义字若照做就会误伤 | 批量替换也生成 issues（每处带上下文），过同一闸口，留变更日志 |
| 4 | **没有工程状态**：哪一章做到哪一步，只在对话和零散文件里 | 换会话、换模型后要重新摸进度 | 每本书一个 `状态.json`，`ytrans status / next` 给出下一步 |
| 5 | **没有段级对齐**：验证只能到章，issues 靠字符串唯一匹配定位 | 核对「可有可无」要临时写脚本找原句 | 原文分段编号，译文按段对应，问题、验证、双语对照都挂在段号上 |
| 6 | **陷阱表只是文字**：写在领域包里，靠模型记得 | 同类错误（括注重复、页码口径）要靠外部审查才发现 | 陷阱表机器可读，每条是一个自动检查，`qa` 每次都跑（回归测试） |
| 7 | **原始 OCR 文本直接当数据** | 卷33 试点 20 条记述 0 条全对（范围符号 95、错字 82、混入图注 30） | 字段分级：未核字段不得用于名录和描述提取（第 4b 节） |
| 8 | **排版依赖 Word 自动化** | Word 存盘卡死 2 次 | 排版独立成模块，可重入；失败不影响译文与数据 |

### 11.2 数据：每类只有一个主库

|---|---|---|

| 译文 | `<书>/译文/*.md`（干净文本，无自动标注） | 唯一人工可改的文本 |

| 工程进度 | `<书>/状态.json` | 每章每模块：未做 / 进行中 / 完成 / 需重做（依赖变了） |

### 11.3 三层分离

```
译文层   干净译文（只有译者写的字；学名斜体、原文括注由译者按规则写一次）
标注层   排版时生成：类群中文名首现加注、「暂定名」标记、术语首现英文括注
         ← 规则 + yiku；改规则只需重排，不动译文
排版层   docx / PDF / 传播版；图位置、目录、参考文献
```
迁移：现有 Rouse 译文里已烤入的标注不回退（风险大于收益）；新书（Handbook）起按三层做，Rouse 下次大修时再迁。

### 11.4 命令（`ytrans`，薄编排层；能复用 yiku 的就放进 yiku）

| 命令 | 作用 |
|---|---|
| `ytrans status <书>` | 读 `状态.json`，列出每章所处模块、待裁定数、报警数 |
| `ytrans next <书>` | 给出下一项可做的任务及其命令或提示词（任何模型照做） |
| `ytrans learn <资料>` | 登记 → OCR → 页文本 → 记述切分 → 候选术语；产物带核对状态 |
| `ytrans terms <章>` | 术语表、缺口、名词委/WoRMS 查询、出处等级 |
| `ytrans examples <章>` | 为形态段落检索志书同类描述（只取已核记述） |
| `ytrans align <章>` | 原文分段编号，建立/校验译文段对应 |
| `ytrans translate / review <章>` | 异模型初译、核译；问题挂段号，带 MQM + 分类学专项类型 |
| `ytrans validate <章>` | 学名、数字、引文、图号；检索表编号与跳转（待写）；陷阱表回归 |
| `ytrans adjudicate <issues>` | 裁定工作单：每条附原句、志书计数与例句、名词委条目，供主会话或用户勾选 |
| `ytrans apply <issues>` | 唯一的改稿入口（含批量替换生成的 issues）；写变更日志 |
| `ytrans publish <书>` | 标注 → 排版 → 图浮动 → 量页 → PDF → 检查；可分步重入 |

### 11.5 开发顺序（先解决出过事的，再做新功能）

1. **`状态.json` + `status / next`**：最小投入，立刻让换模型、换会话不丢进度。
2. **`traps.tsv` + 回归检查**：把领域包第 6 节的陷阱逐条变成自动检查，并入 `qa.py`。
3. **批量替换走闸口**：`unify.py` 改为只生成 issues，不直接改文件。
4. **术语主库统一到 yiku**：脚本改读 yiku；`terms/*.tsv` 改为导出视图。
5. **`align` 段对齐**（Handbook 开工前必须有）。
6. **`adjudicate` 裁定工作单**、**`examples` 例句检索**。
7. **标注层与译文分离**（从 Handbook 起）。
8. 检索表校验、基准测试集（一篇含描述、检索表、比较表的论文，人工标准答案）。

不做的：不重写翻译引擎、不做图形界面、不做 PDF 原位排版；模型调用继续用现有的 `run_batches.py` 与各家命令行。
