# 通用专业翻译系统设计（从分类学实例抽象）

版本 2026-11-10。分类学是第一个、也是最难的实例；本文把其中与领域无关的部分抽出来，形成任何专业领域都能用的翻译流程与软件结构。领域知识全部放进「领域包」，核心不含任何领域常识。

---

## 1. 适用范围

- 专业书籍、论文、报告、标准的翻译（英→中全流程最完整；auto 档语言对可配 `--sl/--tl`，各语言对的支持程度与限制见 `skill/SKILL.md`「语言对与已知限制」，不是所有语言对都同样完整）。
- 共同难点：**术语有规范、原文有不可改动的证据性内容、目标语有本行写法**。分类学是学名与检索表；法律是条文号与法定术语；医学是药名剂量；工程是参数与单位；科学史是人名、学派与经典译名。
- 不适用：文学翻译（追求风格再创造，不以术语与证据为中心）。

---

## 2. 核心概念（领域无关）

| 概念 | 定义 | 关键字段 |
|---|---|---|
| 资料 Source | 一份可引用的文件（权威书、标准、名录、对照译本、论文） | key、kind、lang、pair、domain、tier、sha256 |
| 页 Page | 资料的一页文本 | 文本、方法（文本层/OCR）、核对等级、producer |
| 段 Segment | 待译文本的最小对齐单位 | 段号、原文、译文、位置（章/页） |
| 术语 Term | 一个概念在某领域、某范围内的定名 | en、zh、domain、scope、source+locator、tier、status（候选/已证/已核/暂定/否决） |
| 依据次序 Authority | 领域内来源的优先序 | 由领域包定义 |
| 问题 Issue | 审校发现的一处问题 | 段号、类型（MQM + 领域专项）、严重度、置信度、原句、建议、证据 |
| 裁定 Decision | 对问题或术语冲突的处理 | 采纳/驳回、依据、裁定者 |
| 陷阱 Trap | 犯过的一类错误，变成自动检查 | 模式、正确做法、来源事件 |
| 工程 Project | 一本书或一批文件的翻译任务 | `project.toml`：资料、领域、范围、模型分配、出版设置 |

## 3. 通用流程（十个阶段，每阶段有通过标准）

| 阶段 | 做什么 | 通过标准 | 对应标准 |
|---|---|---|---|
| S0 立项 | 定范围、用途、领域包、依据次序 | `project.toml` 完整 | ISO 17100 译前 |
| S1 解析 | 原文文本化、分章、分段编号；图表抽出并记位置 | 段数、图注数、表格数与原书一致 | — |
| S2 术语 | 逐章术语表；缺口按依据次序查证；查不到标暂定 | 每个术语有出处等级 | ISO 17100 术语准备 |
| S3 样章 | 全流程跑 1–2 章，抽查 | 错误率 ≤ 阈值才铺开 | 试译 |
| S4 初译 | 注入术语表、领域规则、目标语范例 | 段段有译文 | Translation |
| S5 译审 | **另一模型**逐段对照：正反两遍、数字专名、结构计数 | 每条问题挂段号 | Revision（双人原则） |
| S6 验证 | 通用检查 + 领域验证器 | 报警全部处理或说明 | — |
| S7 表述 | 按本行写法核对（目标语规范语料） | 合乎领域写法 | 学科编辑 |
| S8 裁定 | 主会话/专家裁定问题与冲突；用字类先查证据 | 每条有依据 | Subject-matter review |
| S9 出版与回流 | 排版、校样检查；读者与审查意见回流成规则和陷阱 | 交付检查全过；每个错误有「下次由谁拦住」 | 终审 |

改动只有一个入口：任何对译文的修改（含批量替换）都生成问题单，经闸口应用并留日志。

## 4. 领域包（插件）接口

一个领域 = 一个目录，核心按约定读取：

```
domains/<领域>/
  pack.toml          名称、语言对、依赖的通用检查
  authority.toml     依据次序：来源类型 → 层级；「正式记述 vs 顺带提及」等细则
  rules.md           翻译规则（专名、格式、不可改动内容）
  style.md           目标语写法规范（由语料归纳，经人核实）
  traps.tsv          陷阱：模式、正确做法、出处 —— 自动回归
  seeds/             初始术语（权威表、名词委导出等）
  validators.py      领域验证器：check(segments, config) -> issues
  extractors.py      可选：从资料抽结构化数据（如分类学的物种记述）
  benchmark/         领域基准测试：原文 + 专家标准译文 + 标注
```

**同一插槽，不同领域放什么**

| 插槽 | 分类学 | 法律 | 医学 | 科学史 |
|---|---|---|---|---|
| 依据次序 | 志书 > 专著 > 名录 > 名词委 > 论文 | 法律文本官方译本 > 法学辞典 > 名词委 | 药典 > 名词委（医学） > 教科书 | 经典译本 > 名家论著 > 名词委 |
| 不可改动内容 | 学名、命名人年份、计数、检索表 | 条文号、日期、金额、当事方 | 药名、剂量、单位、适应证 | 人名、年代、引文 |
| 目标语写法 | 志书「具/无 + 数字 + 量词」 | 法条句式、「应当/可以/不得」 | 说明书体例 | 经典译本的叙述风格 |
| 领域验证器 | 学名保真、检索表跳转、异名 | 条文号与交叉引用、情态词强度 | 剂量单位换算、禁忌否定词 | 人名音译一致、年代 |
| 结构化抽取 | 物种记述、名称用法、名录 | 条款树 | 药品—剂量表 | 人物—著作年表 |

新增领域只写这个目录，不改核心代码。

## 5. 学习回路（领域无关）

```
加入资料 ──► docstore（登记、文本化、分级）
   ├─ 对照书（原著 + 译本） ──► 按章对齐，抽译者用字 ──► 术语候选
   ├─ 目标语权威论著         ──► 「中文（English）」括注 ──► 术语候选
   ├─ 权威表（名词委、名录） ──► 直接导入                ──► 术语候选
   └─ 目标语本行文本         ──► 表述规律（计数 + 例句） ──► style.md 草案
术语候选 ──► 核验（原页确有此字）──► 按依据次序定名；冲突交人
style 草案 ──► 人工/主会话核实 ──► 领域包
翻译、审校、读者反馈 ──► 陷阱 ──► traps.tsv（自动回归）
```
规则：抽出来的一律是候选；模型自拟的译名只能是「暂定」；OCR 的「0 次」不算证据。

## 6. 模型编排（领域无关）

| 层 | 职责 | 模型 |
|---|---|---|
| 脚本 | 文本化、分段、闸口、验证、排版 | 无 |
| 轻量 | 跑流程、看图核对、机械抽取 | haiku 级 |
| 中等 | 初译、译审（与初译不同模型）、查证、归纳 | sonnet / Codex / DeepSeek |
| 较强 | 多文件实现、中等模型失败后的调试 | opus |
| 顾问/编排 | 设计、分派、裁定、抽查、疑难 | 最强模型 |

协议：任务书写明目标、输入输出、通过标准、禁止事项；子任务失败一次升一级；拿不准写求助，不猜。模型通过适配器调用（各家命令行），流程与模型解耦。

## 7. 软件形态

一个命令行，按组件分组子命令；领域包与模型适配器以插件发现（Python entry points）。

```
<cli> store   add | text | quality | verify | search | page | cite | detect | import    （docstore）
<cli> terms   table | gaps | lookup | import | review | export                          （termbase）
<cli> data    extract | verify | export                                                 （领域结构化数据，可选）
<cli> project init | status | next                                                      （project.toml、状态）
<cli> run     align | draft | review | validate | style | adjudicate | apply             （翻译与审校）
<cli> publish build | float | toc | check                                               （出版）
<cli> bench   run | score                                                               （基准测试）
```

数据都在用户本地（SQLite + 文件），不依赖云服务；任何模型、任何人都能接着做。

## 8. 从分类学实例到通用系统的路径

1. **抽离**：把分类学特有的东西（依据次序、志书写法、学名验证、物种记述）全部移到 `domains/taxonomy/`；核心测试在没有任何领域包时也能跑。
2. **第二个领域验证通用性**：用用户已有的 Nei & Kumar《分子进化与系统发育》英文原著 + 吕宝忠等中译本，建 `domains/molecular-systematics/`（依据次序：经典译本 > 名词委 > 论文）。如果不改核心就能跑通术语学习、翻译、审校，说明抽象成立。
3. **基准测试**：每个领域一份带专家标准答案的小样本，流程每次改动都回归。
4. **命名**：仓库现名强调分类学；通用核心可另起中性的包名（待用户定），分类学作为旗舰领域包。
