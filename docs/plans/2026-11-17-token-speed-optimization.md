# 后续优化计划：省 token · 少依赖模型 · 并行加速（2026-11-17）

**状态：** **Cursor 已落地可测档（2026-11-17）** — 见 [`docs/CURSOR_OPTIMIZATION_2026-11-17.md`](../CURSOR_OPTIMIZATION_2026-11-17.md)。  
默认：lean 开、verify=none、跨书 memory、贵模型需 force、cache_control、关思考。  
**详细验收清单：** [`2026-11-17-fast-lean-book.md`](2026-11-17-fast-lean-book.md)。  
**依据：** `docs/research/2026-11-15/taxo_token_economy.md`；本地库调研；Hartmann usage.tsv。

### 为何设「节约 tokens」护栏（用户动机，2026-11-17）

作者用本软件时**已产生高额模型费用**。用户判断：既已走 **Google 免费初译**，后续就应**极大节约 tokens**，而不是再拿贵模型把全书改写/核对两遍、三遍。

因此护栏不是可选优化，而是**防再烧钱的保险丝**：

| 错误做法（已花钱） | 正确做法（本计划） |
|---|---|
| Google 之后仍全文送 DeepSeek/Opus 改写 | Google + 术语/规则（0 token）为主 |
| revise + check + verify 三轮模型 | 质控最多 **1** 次模型，其余脚本 |
| 会话用 Opus → 流水线也用 Opus | `auto` 选最省够用模型；Opus 仅强制 |
| 开思考「以防万一」 | 无比测增益则关；DeepSeek 已测宜关 |

**验收口诀：** 有 Google 初稿的路径，若仍出现「大段可脚本处理的文本被送进 LLM」，即视为回归失败。

### 分类学术语大量重复 → 必须吃透的加速/省 token 方法

用户指出：分类学书术语极多，**一大部分会反复出现**。这不是「再多调几次模型」，而是**术语层 0-token 杠杆**（研究已量化，见 `docs/research/2026-11-15/taxo_token_economy.md`）。

| 重复落在哪一层 | 实测（德文分类文献） | 能否靠此省模型 |
|---|---|---|
| 整句/从句 | 去重后仍要约译 89% | 否：句级翻译记忆只省约一成 |
| 句子骨架 | 覆盖有限 | 否 |
| **术语与词形** | 约 5 千词形可覆盖 95% 词次 | **是：主杠杆** |
| 标签段（产地/生态/分布） | 去重后可剩一半量级 | 部分：规则+表 |

**必须落地的方法（PR-A/C 与回流挂钩，不是可选项）：**

1. **共享术语库 + 异写表（跨书）**  
   同语言对、同领域共用；Google 稿以原文为锚做 `normalize`（0 token）。异写按**长词优先**，避免 `bristle` 先换破坏 `bristle segment`。
2. **块分流**  
   描述/标签/图注/文献 → 默认不上模型；只 narrative/remarks 或风险段可上（且全书质控 ≤1 次 LLM）。
3. **每书回流**  
   `mine_corrections` / 核对日志 → 审后写入异写与 `google_fixes.tsv`；下一本重复术语直接脚本改。
4. **风险句脚本**  
   数字、否定、学名、长度比、**「原文有术语而定名不在译文」** → 标风险；多数靠补异写消灭，而不是送模型。
5. **短语表慎用**  
   已测：单独译短语收益有限；优先术语异写，不优先堆短语模型调用。
6. **验收指标（写入 report）**  
   - 术语覆盖率（原文命中异写/HARD 的比例）  
   - `google_kept` / `sent_to_model` 段数比（分类书目标：送模型字符 **≤ 约 20%**）  
   - 本跑新增异写候选条数（回流是否发生）

**调研结论（已有）不必重做整句 TM；要做的是把「重复的一半术语」变成表驱动替换，让 Google+表逼近模型改写。** 未完成的是：跨书共享位置固化、回流自动化进报告、第二份文献上实测漏检率（计划 PR-A/C live）。

## 1. 结论摘要

| 问题 | 结论 |
|---|---|
| 大量烧 token 的根因？ | **已定位**：默认全文模型改写 + revise 串行/重试 + revise→check→verify 多遍调用；不是「翻译框架坏了」。 |
| 翻译逻辑对不对？ | **设计对、默认用法错**。正确链路是 Google→脚本/术语→只补缺口；错误默认是全书送模型改写。 |
| 能否 400 页约 30 分钟？ | **机器流水线可以**（折扣窗口内 + lean + 并行）；人审 critical 不进 30 分钟。 |
| 能否少用乃至不用大模型？ | **能**。分类描述书目标：**80–90% 页 0 token**，其余 10–20% 才用模型。 |
| 省 token 与质量？ | **同时要**：极致省是改掉不当调用；质量靠脚本护栏+抽检+人工 critical，不靠多轮模型堆叠。 |
| 分类术语大量重复？ | **杠杆在术语/词形层**（非整句）；Google+异写表+块分流+每书回流；目标送模型字符 ≤≈20%。 |

## 2. 硬约束（不可破）

1. **Google 初译 + 模型校正**必须走**最低 token**；禁止默认全文改写/重译。
2. 校正顺序固定：  
   **脚本/术语（0）→ 只送叙述或风险段 → 模型只回 JSON 最小改动**。
3. 必须有 **`--engine none`（档 0）**：Google + 本地库，零大模型。
4. Google+模型入口未开 lean：CLI **警告或拒绝**。
5. **用一次模型，回流一次经验**：可规律化错误写入术语异写 / `google_fixes.tsv` / 块规则 / 护栏；目标是下一本更少用模型，不是「堆 N 个脚本 = 大模型」。
6. **三遍质控：整条流水线最多调用大模型 1 次**（用户 2026-11-17）。  
   - 另外两遍（及更多护栏）**必须是脚本/确定性检查**，禁止再调 DeepSeek/Codex/Claude 等。  
   - 禁止现行默认的「revise 模型 + check 模型 + verify 模型」三连。  
   - 档 0：模型次数 = 0。档 1：至多 1 次（改写 **或** 核对二选一，不得两轮都上模型）。  
   - 实现上：`auto_translate` / fast path 的 usage 计数若 LLM 调用 > 1（按块汇总策略在 PR-A 定：建议「全书质控阶段合计 ≤1 次批量调用」或「每块至多 1 次」——默认按**每个质控单元至多 1 次，且不得再开第二模型裁定轮**），超限即失败。
7. **极致省 token，同时保质量**（用户 2026-11-17）：凡发现浪费或不当用法，必须改掉，不得保留「方便但费 token」的默认。  
   - **省**：能脚本就不调模型；能相关术语就不送全书表；能 JSON 小改就不重写整段；默认关思考；限 max_tokens；前缀缓存；无回流的模型调用视为不完整。  
   - **保质**：数字/学名/检索表/术语 HARD 护栏 0 容忍；critical 进人工不静默放过；档 0/1 必须以护栏+抽检可验收，不能靠「少调用」偷工。  
   - **审计**：每次跑报告「本可 0-token 却送了模型」的段数；该数 > 0 须可解释，否则算回归失败。
8. **自动选最省合适模型；贵模型默认禁用**（用户 2026-11-17）。  
   - 默认 `--engine auto`：按**任务档**选当前够用的最便宜模型（省 token / 省订阅额度至上），**不**跟随用户会话里正在用的 Opus。  
   - 梯队（从省到贵，能低则低）：`none` → `deepseek-flash`（关思考）→ `claude-sonnet` / `codex-luna` → … → **`claude-opus` / astra 等仅 `--force-engine` 显式强制**。  
   - 用户在 Cursor/Claude 里用 Opus **不等于**翻译流水线用 Opus；流水线各自选模。  
   - 任务→默认模型表写入 `token_economy` / 配置，可随比测更新；报告打印「本任务选了谁、为何不选更贵的」。
9. **思考模式默认关；有疑再测，无增益不开**（用户 2026-11-17）。  
   - DeepSeek：已有比测（`auto_translate` / `llm_engines`，2026-11-14）——**开思考对审校/翻译无明显提质，输出约贵数倍至约 1/17**；默认 `thinking disabled`，禁止默认 `YZZ_DEEPSEEK_THINKING=1`。  
   - 其他引擎：默认最低推理档；只有护栏反复失败且小样比测证明开思考净收益为正时，才允许对**该失败单元**升级，并记入报告。  
   - PR-A 附带小样探针：同段 flash 关/开思考各 1 次，比 major 错误数与 output token；无增益则配置锁定为关。
10. **分类书必须吃「术语重复」红利**（用户 2026-11-17）：共享异写表 + 块分流 + 每书回流为默认路径；禁止对已能表替换的重复术语再调模型。验收见上文「分类学术语大量重复」节。
11. **必须用本地分类资料库，禁止「库里有却去问模型」**（用户 2026-11-17 调研）。  
    家底与做法见 `docs/research/2026-11-17/local_taxonomic_libraries_for_token_economy.md`：  
    docstore ≈2948 份 / 50 万页、分类学 65 份（40 已 text_done）、名称库 1126 中文名 + 多份术语 TSV、ANNiKEY 518、taxa 667 name_usage、已有 Handbook 中译稿可挖异写。  
    译前合并本地表；定名/例句走 `docstore`/`yiku`/名称库；已有译稿 `mine_corrections`；动物志未 text_done 的优先入库以扩大覆盖。
12. **翻过一本，下一本必须更省（跨书积累，强制功能）**（用户 2026-11-17）。  
    **现状问题：** 每书常重新 `--glossary`、经验停在单书 `WORK/`，看起来像「每次从头」。  
    **目标：** 同 **语言对 + 领域**（如 `de→en` + 分类学）共用一份积累库；书 A 结束自动挖候选 → 审后入库 → 书 B **默认自动加载**，无需手工从零建表。  
    **必须实现（PR-A/C，缺则不算完成）：**  
    1. 共享库路径（例：`~/.cache/yzz-translate/memory/{sl}-{tl}/{domain}/variants.tsv` + `google_fixes` 增量；或写入 yiku 异写，二选一，优先不另起炉灶）。  
    2. `auto_translate` / fast path：**默认读取**该共享库；`--glossary` 为叠加而非唯一来源。  
    3. 每书结束强制跑 `mine_corrections`（初稿 vs 终稿）→ `candidates.tsv`；`report.md` 列出待审条数；提供 `memory absorb`（或等价）一键并入共享库。  
    4. 报告对比指标：**本书 sent_to_model 字符占比** vs **同语言对上一本**（应下降或持平可解释）；本地异写命中次数必须打印。  
    5. 禁止「只改本书 glossary、不写共享库」的默认可交付路径。
13. **学习各家「省 token 用法」+ 角色分工（军师 vs 主力）**（用户 2026-11-17）。  
    厂商文档与惯例必须落进调度，不能只写在聊天里：  
    | 角色 | 谁 | 干什么 | 默认 |
    |---|---|---|---|
    | **军师 / 架构** | Opus（或同级最强） | 设计脚本框架、定规则、难例裁决、改软件架构 | **不做批量翻译/逐段校正**；仅 `--force-engine` 或显式 `role=architect` |
    | **主力翻译/校正** | Sonnet / deepseek-flash / luna 等 | 档 1 唯一允许的 LLM 质控轮 | `engine=auto` 按任务选最省够用 |
    | **文书/脚本** | 本地 Python | Google 后处理、术语、护栏、排版、跨书 memory | 默认路径的主体 |
    **缓存与调用习惯（PR-A 写入 `token_economy` / `llm_engines`）：**  
    - DeepSeek / Anthropic：**稳定 system 前缀 + `cache_control`（或等价）**，规则与全书术语放前、每段变化放后。  
    - Claude CLI：继续 `CLAUDE_LEAN`（不加载用户技能/MCP 等固定开销）；批量勿用 Opus。  
    - 输出：JSON 小改、限 max_tokens、关思考（无比测增益不开）。  
    - 文档：`skill/TOKEN_ECONOMY.md` 写清「军师 Opus / 主力 Sonnet·flash」与缓存清单，代理与人共用。  
    **软件能否做到「Opus 设计框架、脚本执行」？能，且应做成默认协作方式：**  
    Opus（人或偶发调用）只产出/修改 **脚本与规则**；之后千页书只跑脚本 + 偶发 flash/sonnet，不再用 Opus 啃正文。

## 3. 根因（实测）

材料：`/mnt/p/翻译-译作/Hartmann-Schröder G/_work/translate/*/usage.tsv`。

| 证据 | 数 |
|---|---|
| 最重一书（1996） | 墙钟 ≈ **421 min**，≈ **4.8 M token**，1438 次调用 |
| 其中 revise | **635** 次（输出 token 主因） |

故：费用与时间主要花在「不该送的描述段也被全文改写」，再叠多遍与重试。

## 4. 正确翻译逻辑（保持，改默认）

```
Google 免费初译（0 token）
  → 【质控① 脚本】术语异写 / google_fixes / 文献·异名录·索引 / 数字·学名·检索表护栏（0）
  → 【质控② 至多 1 次模型】二选一：lean 改写叙述段 或 risky-only JSON 核对（不可两轮都上模型）
  → 【质控③ 脚本】再次护栏 + taxoformat + apply_issues 闸口 + 风险页清单（0；critical 进人工，不调第二模型）
  → mine_corrections → 回写入库 → 下一本更省
```

旧默认（**废除**）：模型 revise → 模型 check → 模型 verify。

| 档 | 名称 | 模型次数 | 何时用 |
|---|---|---|---|
| **0** | 零模型 | **0** | **默认先跑**；出可抽检稿 |
| **1** | 最低 token（lean） | **≤ 1** | 档 0 不够时；改写或核对择一 |
| **2** | 全文/多轮模型 | >1 或全文改写 | **禁止默认**；仅显式 `--full`（且须警告费 token） |

叙述/讨论不能靠堆脚本完全替代模型；术语与电报体描述可以、且应该脚本化。

## 5. 实施 PR（落地顺序）

```
trunk
  ├─ PR-A  省 token 调用层 + lean 默认 + engine none + 回流钩子   ← 先做
  ├─ PR-B  revise 块并行 + 多章并行
  └─ PR-C  一书 fast path（ETA/预算 + 端到端）
        └─ PR-D  调用面模块收敛（删重复 max_tokens=64000 等）
              └─ PR-E  质量抽检闸（审查门控）
```

| PR | 一句话 | 主要验收 |
|---|---|---|
| **A** | 统一省 token：关思考、任务档限输出、缓存、`--lean`、`--engine none`/`auto` 选模梯队、未 lean 拒绝；**质控默认至多 1 次 LLM，去掉第二模型 verify**；Opus 仅 `--force-engine`；**译前合并本地名称库/ANNiKEY/yiku，报告本地覆盖率** | 试点送模型段 ≤ 叙述+讨论；none 无 LLM；默认路径无第二引擎、无 opus、无 thinking；`auto` 选模可单测；报告含本地表命中率 |
| **B** | 块/章并行，写路径隔离 | j=4 revise 墙钟明显低于串行；产物一致 |
| **C** | 一条命令 Google→lean→risky check→taxo→report；先打印 ETA；**结束强制 mine→共享库候选；下一本 auto 加载共享库** | 样章墙钟 ≤ 旧路 1/3，token ≤ 1/2；400 页外推 ≤ 30 min；第二本同语言对在加载共享库后 `sent_to_model` 低于第一本（或命中异写次数明显上升） |
| **D** | 一处调用入口；compact system | 全测通过；不回退 C 的 perf |
| **E** | 护栏+抽检不过不能宣称完成 | 故意坏页 → 非 0 退出 |

勾选级细节、文件列表、unit/live/perf 失败线见 `2026-11-17-fast-lean-book.md`。

## 6. 经验闭环（与 A/C 一起做）

每跑完一书，`report.md` 必须列出：

- 本跑 `sent_to_model` / `google_kept` / 0-token 段占比  
- **可入库候选**：异写、google_fixes、新风险信号  
- 无候选且用过模型 → 标「回流缺失」（fast path 不完整）

长期指标（写入报告，不另造系统）：  
**0-token 覆盖率 ↑，送模型字符数 ↓，usage 美元 ↓。**

## 7. 明确不做

- 不重写整个翻译引擎、不换供应商框架  
- 不把人工 critical 审阅读进 30 分钟  
- 不默认白天跳过 DeepSeek 折扣  
- 不为并行共写同一缓存/产物文件  
- 不宣称「脚本数量 = 大模型能力」  
- **不做默认的第二模型 verify/裁定轮**（与「至多 1 次 LLM」冲突；异模型审校改为可选、显式、且计入后即超限须 `--full`）
