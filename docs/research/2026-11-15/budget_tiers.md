# 按预算分档的翻译方案（分类学专著）——调研与实测（2026-11-15）

用户要求：「没钱也可以用 Google 翻译结合廉价模型整理成书；有钱可以选不同组合；分类文献大部分是电报体分类用语，应该很容易节约 tokens，只有前言、讨论等需要好好翻译」。
本文先量化「哪些文字需要好好翻译」，再给分档方案。各档的模型名次待今晚直译比测（`_比测/2026-11-15_模型直译对照`）出结果后补。

## 1. 一本分类专著里各类文字的占比，以及 Google 初稿离终稿有多远

材料：Marinov 1977（保→英，265 页）。Google 初稿（`work/trial/C_google_full.md`）与全流程终稿（D3：改写 + 两模型核对 + 目录核图）按段 ID 对齐。
「相似度」= Google 初稿与终稿的字符相似度（1 = 终稿没改）。

| 文字类型 | 字符占比 | 相似度中位 | Google 初稿基本可用（≥0.8）的段 | Google 术语错 / 段 |
|---|---|---|---|---|
| 叙述（前言、讨论、生物学、分布叙述） | 41% | 0.82 | 60% | 0.95 |
| 电报体描述（体长…；口前叶…） | 24% | 0.88 | 70% | 0.66 |
| 标签段（Colour. / Length. / Distribution. / Bionomics.） | 12% | 0.86 | 75% | 0.54 |
| 检索表 | 9% | 0.87 | 81% | 1.05 |
| 异名录 | 7% | 1.00 | 99% | 0 |
| 图注 | 4% | 0.75 | 24% | 3.74 |
| 标题 | 4% | 1.00 | 97% | 0 |

结论：
1. 用户判断对：**真正需要模型认真改写的是叙述（约 41%）和图注（4%）**；异名录、标题基本不用改；描述、标签段、检索表 Google 初稿七八成可用，**主要错在术语**（setae/bristles、parapods、palpi、Bionomy、Table for determining）。
2. 图注最差（术语最密、子图字母被 Google 改成拉丁字母），应当和叙述一样认真处理。

## 2. Google 稿与终稿的差异是否成系统（能否「零成本」处理）

**更正（用户 2026-11-15）**：下面这些差异大多不是 Google 的「错」，而是**本项目的用语约定**（setae 与 chaetae 都是合法英文，老文献常用 setae）；
原文作者自己的用语（旧术语、旧体系）更不能当错误改掉——忠实原文是翻译的基本准则。所以修正只能依据**本地库**（项目术语表 / yiku）
登记的定名与异写，并**以原文为锚**：原文这一段出现库里的源术语，才规范译法（`transqa/terms.py`）。

逐词比对 Google 初稿与终稿：17,984 处改动中，**同一短替换出现 ≥5 次的 269 组覆盖了 29%**（setae→chaetae 225 次，cirrus→cirri 224，Bionomy→Bionomics 104，Color→Colour 103，Table for determining→Key to 94，parapod→parapodium 81，palpi→palps 44，branch→ramus 58，front→anterior 66，子图字母 a→а 202 等）。
但能**不看上下文直接替换**的（该写法出现时 ≥80% 被改成同一写法）只有 29 组、622 处（`work/qc2/google_fix_table_bg_en.json`）；setae、bristles、parapods 这类大头随单复数和搭配变化（hair-like setae → capillary chaetae），须按术语表的「禁用译名」规则替换，不能用一张死表。
→ 零成本档的术语修正走通用机制：本地库的「异写」列（`源术语 | 定名 | 异写`，`setae=chaetae; seta`），以原文为锚替换（`transqa.terms.normalize`，已接入 `auto_translate.stage_revise`）；
`--engine none` 即档 0：不调模型，只用 Google 初稿 + 确定性处理 + 本地库术语 + transqa 检查。挖出的替换对只作为**候选**交人工确认后进库，不直接使用。

## 3. 分档方案（成本以 265 页、约 70 万原文字符的书估算）

实测单价：DeepSeek flash 闲时输入 $0.15/M（缓存命中 $0.003/M）、输出 $0.6/M；9 页改写实测 $0.011（含一次重做），全书全文改写约 $0.3；DeepSeek 全书找错约 $0.02–0.08；Codex、Cursor 为订阅额度（不计价，但有 5 小时/周上限）；Google gtx 免费（8 线程约 320 段/分钟，全书约 15 分钟）。

| 档 | 适用 | 流程 | 估算花费 | 质量预期 / 风险 |
|---|---|---|---|---|
| **0 零成本** | 只求能读、自用速查 | Google 初稿 → 确定性处理（异名录/文献/索引原样+转写；专名 yiku/Wikidata；术语禁用变体替换；子图字母、图版号）→ transqa 检查（数字、学名、检索表、页序、残留）→ 人工队列 | $0（无模型） | 描述、检索表大体可用；**叙述的意思错不会被发现**（无意义核对） |
| **1 省钱** | 大多数分类专著 | 档 0 + 只把**叙述、图注、检索表**送 DeepSeek flash 关思考改写（夜间）；描述、标签段用 Google+术语表；DeepSeek 找错 + 订阅模型（codex-sol）复核，只落实两者都认可的 | 约 $0.15–0.2 + 订阅额度 | 叙述得到改写与核对；描述只有术语级修正 |

| **3 高质量** | 经典著作、要与名家译本比肩 | 叙述段由较强模型直译（今晚比测定：Sonnet / codex-sol / DeepSeek 思考），两家不同模型复核；检索表、描述按档 2；人工专家终审 | 订阅额度为主；若走 API 按量计 | 以《生物学思想发展的历史》中译本、葛颂《生物进化》为临时基准 |

## 4. 省 token 的通用做法（与档位无关）

1. **按块类型分流**（已实现 `transqa.blocks.classify`）：异名录/文献/索引 0 token；描述/标签段在档 1 只做术语级修正；叙述与图注才用模型。
2. **稳定前缀缓存**（已实现）：规则 + 全书术语表 + 转写表字节不变，DeepSeek 缓存命中价约为原价 2%。
3. **只送超标段润色**（已实现 `zh_polish`）。
4. **学习 Google 的系统性错误**：每完成一本，用「Google 初稿 vs 终稿」挖出一致性 ≥0.9 的替换对，经人工确认进 yiku 的禁用变体；下一本同语种、同类群书零成本修正（待实现：自动挖掘 + 审核表）。
5. **描述的翻译记忆，收益有限**：实测 Marinov 描述句 2,695 句，把数字、学名归一后仍只有 **17%** 精确重复，且多是「до # mm.」这类短句。
   句级翻译记忆省不了多少；省钱的大头在术语级修正（§2）和按块分流（§4.1），而不是整句复用。
