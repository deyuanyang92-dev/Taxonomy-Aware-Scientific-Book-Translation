# 多语种分类术语 → 英文义项 → 中文：方案 v0.3（2026-11-23）

状态：经 Codex（gpt-6.1-sol）对抗审核两轮；本版按第二轮「开工前最少清单」6 条修订，并加入用户 2026-11-23 要求的「专家修订全程留痕、可退回、可多选一」。未实施；是否第三轮审核由用户定。
审核原文：`docs/plan_multilingual_terms.codex_review.md`（第一轮）、`docs/plan_multilingual_terms.codex_review2.md`（第二轮）。各版修改见文末「修订记录」。

## 1. 目标与约束

- 源语言（西、日、法、德、俄、葡、意……）的分类术语要准确译成中文；英文作为各语言共用的检索标签（义项中枢），不强制全文两跳翻译。
- 尽量自动，支持人工；人工裁定后在其声明的适用条件内自动复用。
- 约束：术语只进 yiku（单一主库）；页面证据在 docstore；默认不用大模型（2026-11-22 规则，仅用户点名开启，单次 ≤5 页）；一本书翻译费用 ≤ ¥2（范围见第 9.4 节）。

## 2. 核心原则

1. **候选自动发现，执行另设门槛。** 共现、同源转写、文内括注、摘要对照都只产生候选，不能互相投票升为可用。
2. **映射目标是义项，不是英文拼写。** 一个拼写可有多个义项（如 hook），多个拼写可属一个义项（branchia / gill，经证据确认后）。
3. **库内唯一 ≠ 语境唯一。** 自动执行必须证明「当前这一处」满足登记的使用条件；证明不了就拒判（第 4 节）。
4. **资格只有一个出口。** 能否自动执行只由统一接口 `eligible()` 判定；旧入口不授予新资格（第 5 节）。
5. **验收从原文出发，不从日志出发。** 逐处三方核对：原文应处理位置、执行记录、最终输出（第 10 节）。
6. **只追加，不覆盖。** 证据、裁定、中文定名、专家修订都是带版本的记录；任何改动都生成新版本并保留旧版本，可退回（第 6、13 节）。
7. **拒判优先于猜。** 未知、冲突、多义、条件不满足、判科不明，一律保留原词进待处理队列，不静默选择。

## 3. 数据模型（扩展 yiku）

| 表 | 内容 |
|---|---|
| `senses` | 义项：稳定 id、英文标签（可多个）、domain、定义（可引 en_glossary）、状态（启用/停用，停用不删） |
| `zh_names` | 中文定名：sense_id、中文、来源与依据、版本号、状态（已核/候选/否决）；一个义项同时只能有一个「已核·现行」中文 |
| `forms` | 源语言词形：lang、原形（永久保留）、检索键（归一化）、显式词形变体 |
| `links` | 词形 → 义项的映射：form_id、sense_id、scope、使用条件 cond_id、状态、版本号 |
| `conditions` | 使用条件（第 4 节）：类型（短语整体 / 结构位置 / 逐处确认）、参数、版本号 |
| `evidence` | 证据：link_id 或 zh_name_id、方法、docstore 资料 key + 页码 + 页面版本 + 定位、证据家族、抽取器版本 |
| `verdicts` | 裁定与否决：作用对象（link 或 zh_name）、通过/否决/撤销否决、理由、裁定人、时间；否决按词对，不按源词整体 |
| `revisions` | 专家修订与裁定的追加日志（第 13 节），只插入不更新不删除 |
| `runs` | 运行清单：输入原文 sha256、规则版本（git commit）、每个自动决定引用的依赖版本；可重建，不进主库 |

试点只给几十个义项建表，不重构全库 17365 条。旧数据（`cand_ja.tsv`、term_presub 的 map.tsv）迁入后一律为候选，英文列为空的不当作映射。

### 3.1 不变量与决策表

| 情况 | 结果 |
|---|---|
| 一个词形在当前 scope 下有 ≥2 个未否决的 link（含候选） | 拒判（多候选） |
| `links.scope` 与当前出现位置的 scope 不相交，或当前 scope 未知 | 拒判 |
| 义项没有「已核·现行」中文，或有 ≥2 个 | 拒判 |
| 同一对象上通过与否决并存且无后续裁定 | 拒判，进裁定队列 |
| 正向裁定 | 不清除既有否决；撤销否决须单独一条「撤销否决」记录 |
| scope 求交 | link 的 scope ∩ 位置 scope 非空才继续；scope 层级（科→目→纲）试点不做，只做字符串相等或显式包含表 |

## 4. 自动执行条件（替代 v0.2 第 4 节第 3 条）

自动执行必须**同时**满足：
1. **源词 → 义项**：link 状态已核，有已核证据（核过 docstore 原页、对应关系明确）。来源等级只决定核查先后，不放行。
2. **义项 → 中文**：恰有一个已核·现行中文定名。只有英文命中、没有中文依据时，不自动定名。
3. **scope**：当前位置 scope 已知，且与 link 的 scope 相交（3.1 表）。scope 只是条件之一。
4. **使用条件**：当前出现满足 link 登记的使用条件，三类之一：
   - **短语整体**：只在已核多词术语整体命中时执行（如「cerdas compuestas」），单词单独出现不执行；
   - **结构位置**：只在指定结构内执行（检索表特征行、描述段的特征项、图注标签），叙述段不执行；
   - **逐处确认**：没有可机读条件的词，每处出现进人工队列，确认后才算该处通过。
   没有登记使用条件的 link 一律按「逐处确认」处理。「库内没有第二个义项」不构成单义证明。
5. **无否决、无冲突**：3.1 表全部通过。
6. **证据去重**：按证据家族计数；同一本书的术语表、括注、共现算一个家族；系统生成的译稿不能回流作证据；家族不明的证据不算独立证据。

## 5. 统一资格接口，封旧入口

- 新增 `yiku.eligibility.eligible(occurrence) -> Decision(ok, reason, deps)`：唯一判定处；`deps` 列出所用 link、zh_name、condition、evidence、verdict 的 id 与版本号，写入运行清单。导出、CLI、网页写回、预替换全部调用它。
- 旧入口不授予新资格：
  - `scripts/term_presub.py:113–115、165` 读任意 TSV 直接替换 → 新流程中只作候选生成；直接替换模式加显式标记 `--legacy-unguarded`，产物标「未受新闸口保护」，不得进入本方案验收。
  - `yiku/yiku/classify.py:64–65` 让高层级来源的候选学名成为 HARD → HARD 仍用于旧翻译提示词，但 `eligible()` 不读 HARD。
  - `yiku/yiku/cli.py:208` `review apply` 原地 `UPDATE terms` → 改为写 `revisions` + 生成新版本（第 13 节），不再覆盖。
- 测试：对上述三个旧入口各写一条回归测试，断言其产物不会让 `eligible()` 返回 ok。

## 6. 版本与撤销

- 稳定 ID：senses、forms、links、zh_names、conditions 的 id 一经发出不复用；停用不删除。
- 每个自动决定的依赖 = `eligible()` 返回的 `deps`（含 docstore 页面版本、规则 git commit）。
- **任一依赖变化即撤销资格**，包括中文侧：中文定名被否决、改字、换来源、缩小范围；证据页被重新 OCR 或校正；使用条件改版。受影响的历史结果按依赖索引查出，标「待重检」。
- 运行快照只用于解释历史（当时为何这样译），不能证明现在仍有效。
- 否决一条映射或撤销一个中文定名，能列出全部受影响的运行与位置（验收项）。

## 7. 候选发现方法（全部只产生候选）

| 方法 | 适用 | 说明 |
|---|---|---|
| 术语表/图解（A 源） | 所有语言 | 核查优先级最高；OCR 与跨行错配需核原页 |
| 平行译本共现 | 有译本者 | term_presub learn；只作候选生成器（缺陷见第 8 节） |
| 文内括注、Resumen/Abstract、双语图注与检索表 | 所有语言 | 括注最可靠；摘要只作候选 |
| 同源转写规则 + 英文词表模糊匹配 | 西葡意法德拉 | 保留并单独评测；是否为罗曼语族「主力」由试点数据定（未确证） |
| 同种记述对照 | 暂缓 | 不是平行文本；只作检索线索 |
| 模型从候选中选择 | 默认关 | 仅用户点名开启，结果只到候选 |

## 8. 现有实现的缺陷（已核源码；修复按需，不前置）

- `scripts/term_presub.py:122`：纯字符串替换，无词边界、无保护区间 → 西语 `cerdas` → ` chaeta s`。
- `scripts/term_presub.py:104`：`--deny` 否决源词整体，不是词对。

- `scripts/term_presub.py:44、93–109`：对齐长度假设 `len(e)*3`、只按英文单词与六字母前缀统计，不支持完整多词术语。

- 试点**不复用** term_presub 做执行器；候选生成若复用，须先补多词术语、来源定位，并对西语重验对齐。

## 9. 试点（西语，多毛类，一个明确类群）——先冻结再跑

### 9.1 材料与金标准
- 1 份学习、1 份调参、≥2 份盲测，按作品家族隔离；盲测材料在规则冻结前不打开结果。
- 30–50 个已核义项：覆盖普通名词、多词术语、词形变化、歧义词、普通用法同形词（专测第 4 节条件）。
- 金标准：盲测材料中标注全部术语出现位置（目标 300 处，不足如实报），含正文、图注、检索表；每处记源位置、义项、允许英文标签、中文译名、依据、「应拒判」标记。由主会话依原页标注，标注时看不到待测输出；用户随机抽查约 20 处（仅作监督：20 处全对，单侧 95% 错误率上界仍约 13.9%）。
- 新语言、新文体或规则大改后，金标准须补验证，不能沿用。

### 9.2 分两阶段
- **阶段 A（零模型，先做）**：只测术语识别与决策——原文枚举、`eligible()`、拒判、逐处日志、三方核对中的前两方。不调用翻译引擎，费用 ¥0。
- **阶段 B（端到端，需用户批准）**：三路径对照——无术语干预源→中；已核术语约束源→中；已核术语约束源→英→中。三路径用同一引擎、同一配置，只改变术语处理方式。

### 9.3 冻结项（盲测前写入运行清单，之后不改）
- 规则版本：git commit；义项与条件版本：yiku 快照 id。
- 引擎（阶段 B）：**待用户指定**。建议 `deepseek-flash` 非思考模式、temperature 0、离峰时段、关闭结果缓存复用；单次 ≤5 页。
- 分母：金标准全部术语出现位置（词次）；拒判率、自动处理率同用此分母；另报词型数。
- 严重错误：自动放行的义项错误；替换破坏学名、数字、引文、检索表结构；词内误替换。
- 通过条件见第 10 节；本轮门槛冻结，试点后调整的目标只用于下一轮，并同时报告原门槛下的结果。
- 盲测失败：结果只用于诊断；修改后另设未见过的盲测材料。

### 9.4 费用范围
- 「一本书 ≤ ¥2」指整本书的翻译流程模型费用（初译、核译、重试）；候选学习与阶段 A 不用模型。
- 试点阶段 B 的模型费用单列，开跑前报预估给用户批准；人工核查时间另记，不折算进 ¥2。

## 10. 验收标准

### 10.1 三方核对（独立验收）
- **E（应处理）**：由独立枚举器从冻结原文枚举全部候选出现——所有已登记词形（含候选和已否决的）+ 金标准位置；枚举器不读执行记录。
- **X（执行记录）**：执行器写的逐处日志。
- **O（输出对应）**：在最终译文对应句段中定位目标中文；翻译引擎改写、丢失、移动术语时定位失败。
- 每个 E 位置必须落在且只落在一个状态：自动通过（X 有记录且 O 核到）、拒判待处理、未识别、无法定位。只有第一种计入「自动正确」；后三种不得记为通过，全部列出。
- X 中有但 E 中没有的记录、同一 E 位置对应多条 X，均为错误。
- 本机制只证明已覆盖术语；未登记的新术语另做独立随机抽查，不宣称由本机制证明。

### 10.2 通过条件（第 9.3 节冻结）
- 自动接受部分：盲测无严重错误；出现一例错误放行即暂停对应 link 或条件。
- 预设的歧义、普通用法同形词、未知、冲突、否决样例全部拒判。
- 覆盖收益（暂定目标，非现有能力）：自动正确 ≥50% 术语词次；最终中文术语错误比基线降 ≥50%。基线错误为 0 时不报相对值，改报绝对错误数与差值。
- 冻结输入可重放同样决定；任一依赖变更能列出全部受影响结果（含中文侧变更）。
- 分别报词型、词次、来源家族及置信区间；50 条全对的单侧 95% 错误率上界约 5.8%，不得据小样宣称低错误率。

## 11. 实施顺序

1. **最小闭环**：几十个已核义项 + 新表（只导入试点数据）+ `eligible()` + 原文枚举器 + 三方核对 + 旧入口回归测试 + `revisions` 追加日志与 `yiku rev` 命令（第 13 节）。
2. 阶段 A 试点，出错误分析。
3. 用户批准后阶段 B。
4. 依错误分析决定：是否修 term_presub 作候选生成器、是否全库迁移、网页首版、自动判科与科档案、其他语言词形规则。

## 12. 与 Codex 审核的分歧与表态

- 第一轮 1–15 条问题本身同意；第 8 节代码问题已核源码。「已核实」不等于「已修复」。
- 同源转写：保留并单独评测；第二轮指出上轮并未要求降级，「主力」之说改为未确证，由试点数据定。
- 金标准：同意第二轮的条件——同一已验证范围内可复用，新语言/文体/规则须补验证；标注者不得看待测输出。
- 两个 50% 目标：同意第二轮意见，只作本轮冻结门槛，不事后改。
- 网页先定协议再做界面：同意（第 13 节）。

## 13. 专家修订：协议、留痕、退回与多选一

用户 2026-11-23 要求：每个专家的每次修改都有记录；可以退回；多个专家意见不同时可以选择哪个正确。

### 13.1 记录模型（`revisions` 追加日志）
每条修订一行，只插入，不更新、不删除。字段：
- `rev_id`（UUID，网页端生成；重复导入同一 rev_id 无副作用）、`package_id`（导出包）、`parent_rev`（回应或退回的那一条）
- 作用对象：`obj_type`（link 映射 / zh_name 中文定名 / evidence 证据确认 / form 新词形）、`obj_id`、`base_version`（专家看到的对象版本）
- 操作 `op`：建议通过、建议否决、建议改中文（附新值）、建议新增词形（默认候选）、无法判断·请求补证、跳过
- `reason`（必填，跳过除外）、`claimed_reviewer`（专家自填）、`created_at`
- 导入信息：`imported_by`、`imported_at`、源文件 sha256
- 状态（由后续记录推出，不改原行）：待裁定 → 已采纳 / 未采纳 / 已退回 / 已撤销

裁定也是 `revisions` 的一行（`op` = 采纳、不采纳、退回、撤销采纳），`parent_rev` 指向被裁定的修订，必填理由和裁定人。

### 13.2 采纳、多选一、退回、撤销
- **多选一**：同一对象的多条待裁定修订并排显示（专家、时间、基础版本、新值、理由、证据），裁定人选一条采纳，其余自动记为「未采纳」并留理由；也可都不采纳。
- **采纳**：生成该对象的新版本（`adopted_from = rev_id`），旧版本保留；触发第 6 节撤销与重检。外部修订默认只是建议，只有本地裁定人采纳后才生效。
- **退回**：把修订退给专家（附原因，如请求补证）；专家再次提交时 `parent_rev` 指回，形成讨论链。
- **撤销采纳 / 回到旧版**：新增一条「撤销」记录，对象回到指定旧版本（同样生成新版本号，不删历史）。
- **查历史**：任一对象可列出完整时间线——谁在何时基于哪个版本提了什么、谁裁定、理由、当时的值。

### 13.3 命令（先做 CLI，网页只是前端）
- `yiku rev import <jsonl>`：严格校验字段、对象 ID、操作类型、大小；先完整校验与预览，确认后在单个事务中写入；失败不留半截状态。
- `yiku rev queue`：列出待裁定，按对象分组显示冲突。
- `yiku rev adopt|reject|return <rev_id> --reason ...`、`yiku rev revert <obj> --to <version> --reason ...`
- `yiku rev history <obj>`：对象时间线。
- 现有 `yiku review apply` 改为通过本协议写入（第 5 节）。

### 13.4 版本与冲突
- 导出包带 `package_id`、每个对象的 `base_version` 及必要依赖版本；导入时逐对象比较，不用全库 hash。无关对象的改动不阻断；对象已变化的修订标「基础已过期」，仍入日志，进待裁定并显示当时与现在的差异。
- 导入后对合并状态重算资格；同义项多中文、同 scope 多义项、通过与否决并存，全部进待裁定队列。

### 13.5 网页（首版范围）
- 单个静态 HTML，数据内嵌 JSON，离线可用。首版只做：按任务分包查看；每条显示源词→义项、义项→中文两段证据（资料名+页码+裁图）、义项定义与使用条件；操作为建议通过/否决/改中文/无法判断·请求补证/跳过 + 理由；导出修订 JSONL。
- 草稿：显示未导出改动数；可下载草稿、重新载入草稿；导出后给完成回执。
- 裁定视图（第二步）：读入多个修订文件，同一对象并排显示，裁定人选择后导出裁定 JSONL，经同一 `yiku rev import` 写入。
- 安全：内嵌数据安全序列化，文本一律以文本节点渲染；不接受 HTML、脚本、远程资源。
- 隐私：发出的审校包只含白名单字段和必要裁图，不嵌本地绝对路径；发出前检查完整包。审校人姓名只出现在返回的修订文件里。
- 后置：新增词形的编辑界面、本地服务（若做，除只监听 127.0.0.1 外还须校验请求来源、禁止跨站写入、限制文件访问范围）。
- 不做：在线公开发布（发布到外部服务需用户逐次确认）；网页直接改主库。
